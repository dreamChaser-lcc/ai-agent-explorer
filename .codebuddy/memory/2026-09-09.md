# 2026-09-09

## GitLab MCP 环境配置调查
- 用户环境已装 `gitlab-mcp@latest`（npx stdio），`GITLAB_API_URL=https://gitlab.vzan.com/api/v4`，当前 `GITLAB_TOOLSETS=core`，MCP 名称为 `GitLab`。
- 该 MCP 所有工具名带 `gitlab_` 前缀；注册表共 211 个工具，按 toolset 分组（core / projects / repository / merge-requests / issues / pipelines / releases / labels / work-items 等）。
- 关键结论：仓库/合并请求的**写操作与部分高级读操作**（如 `gitlab_create_branch`、`gitlab_get_branch_diffs`、`gitlab_create_merge_request`、`gitlab_merge_merge_request`、`gitlab_get_merge_request_conflicts`、`gitlab_get_merge_request_approval_state` 等）位于 `repository` / `merge-requests` toolset，core 下默认禁用；需把 `GITLAB_TOOLSETS` 改为如 `core,repository,merge-requests`（或 `all`）并重连才能暴露。
- 可用 `gitlab_discover_tools`（支持 query/capability/toolset/include_disabled/limit 参数）自查工具启用状态。
- 补充：`gitlab_search_repositories` 真实存在（scope global，仅 `projects` toolset，默认 disabled）；用户要精确启用工具时应双开关：`GITLAB_TOOLSETS=core,projects,repository,merge-requests` + `GITLAB_ALLOWED_TOOLS=<逗号分隔的 gitlab_* 工具白名单>`（支持省略前缀）。工具须同时满足 toolset 候选与白名单才会暴露。
