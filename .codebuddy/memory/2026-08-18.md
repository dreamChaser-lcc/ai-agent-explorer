## Java/Spring Boot 教学对话（面向前端背景用户）

- 用户为前端（JS/TS）背景，通过阅读自身项目（ai-agent-explorer backend）源码学习 Java 后端，教学方式为：类比/图表 + 项目真实代码 + 简洁总结，反馈良好。
- 推荐了学习资源：Spring 官方文档（spring.io/projects/spring-boot）、Spring Initializr（start.spring.io）、Spring Guides、springdoc.cn 中文文档镜像、B 站黑马/尚硅谷 Spring Boot 教程、JavaGuide、廖雪峰 Java 教程。
- 建议用户采用"逆向学习法"：从 ResearchTaskController 的请求链路逆向拆解 Controller → Service → Repository 每层注解。
- 讲解了 JS/TS 开发者常踩的 Java 语法坑（按重要程度）：
  1. String 内容比较必须用 equals()，== 是比地址
  2. Integer 缓存池 -128~127，包装类比较用 equals()，拆箱可能 NPE
  3. null 空指针 NPE 需判空，可用 Optional
  4. Java 参数永远是值传递（引用拷贝）
  5. 受检异常必须 try-catch/throws
  6. 泛型运行时擦除，不能 new T()
  7. 数组协变但运行时检查 ArrayStoreException
  8. 无默认参数，用重载/Builder
  9. 金额计算必须用 BigDecimal
  10. Stream 惰性求值，需终端操作触发
  11. switch 不写 break 会穿透（可用 case -> 新语法）
  12. final 只是锁引用，内容可变
  13. 杂项：arr.length 无括号 / 静态方法不能 @Override / 重写 equals 必须重写 hashCode 等
- 核心总结：JS 相信你、Java 怀疑你，Java 坑的本质是"过于严格"。

## 后续教学内容

- **Maven vs Gradle**：Maven=pom.xml 声明式"填表"、Gradle=build.gradle 编程式"写程序"；Gradle 更快（增量构建/缓存/并行/守护进程）；类比前端：Maven≈npm+固定脚本，Gradle≈pnpm+可编程流水线。项目用 Maven。
- **查注解的方法**（以 @Bean 为例，项目 AsyncExecutionConfiguration.java:17）：
  1. IDE Ctrl+点击注解名跳到源码，看 @Target/@Retention/Javadoc 注释（最推荐）
  2. 官方 Javadoc：docs.spring.io/spring-framework/docs/current/javadoc-api/；JDK 注解用 docs.oracle.com
  3. 官方参考文档/springdoc.cn 中文镜像（讲用法细节）
  4. 搜索引擎中文博客（注意以源码注释为准）
  - 演示了 @Bean 含义：方法级注解，把返回值注册进 Spring 容器，方法参数由容器自动注入。
- **Lombok @Getter 原理**（@Retention 概念延伸）：
  - @Getter 是 RetentionPolicy.SOURCE，只活源码阶段，编译后消失（对比 Spring/JPA 注解是 RUNTIME）
  - 真正干活的是 javac 注解处理器（Annotation Processor）：javac 通过 META-INF/services 发现 Lombok 处理器，在编译期修改内存 AST，把 getXxx() 塞进代码树，最终 .class 里确实有方法
  - 类比前端：Babel 插件把 JSX 转 createElement = Lombok 把注解转 getter（编译期代码生成/宏）
  - IDE 能补全是因为装了 Lombok 插件（编辑阶段模拟同样逻辑）；javac 不需要插件
  - pom.xml 的 annotationProcessorPaths 是 Java 9+ 后为 javac 显式指定处理器路径
  - 验证方法：mvn compile 后 javap -classpath target/classes ...TaskEventLogEntity
- **@Setter 同 @Getter 原理**（同一 Lombok 处理器，编译期生成 setXxx）
- **@Entity 对比**（关键区分 SOURCE vs RUNTIME retention）：
  - @Entity 是 RetentionPolicy.RUNTIME，编译后留在字节码，纯标记不生成代码
  - 干活的是 Hibernate（运行期）：启动时扫描 @Entity 类 → 读 @Table/@Column/@Id 建立映射元数据 → 运行期按元数据动态生成 SQL
  - 对照表：SOURCE 编译期生成代码（Lombok/Getter、Setter）| RUNTIME 纯标记运行期反射（@Entity/Hibernate、@Service/Spring）
  - 前端类比：Lombok≈Babel 插件（编译改写）；@Entity≈TypeORM 的 @Entity() 装饰器（运行期元数据）
- **Hibernate 讲解**（用项目真实链路 TaskEventLogRepository / TaskEventLogEntity / ResearchTaskQueryService）：
  - Hibernate = ORM 框架，负责 Java 对象↔数据库表的双向翻译（类比 TypeORM/Prisma）
  - 三层关系：Spring Data JPA（接口层，方法名解析成 SQL，如 findByTaskIdOrderByCreatedAtDesc）→ Hibernate（JPA 规范实现，ORM 引擎）→ JDBC → 数据库
  - Repository 接口运行期由 Spring Data JPA 动态代理生成实现类，无需手写实现
  - save() 根据 id 是否为空决定 INSERT/UPDATE；findById 生成 SELECT
  - 项目配置 ddl-auto: validate → Hibernate 只校验不建表，表结构由 Flyway 管理（生产级做法）
- **JPA vs MyBatis 对比**（结合项目 8 个 Repository 实例讲解，全部无 @Query，靠方法名解析）：
  - JPA=框架自动生成 SQL（方法名解析：findByTaskIdOrderByStepNoAsc → WHERE task_id=? ORDER BY step_no ASC）；MyBatis=手写 SQL（mapper 接口 + XML 两处都要写）
  - JpaRepository 空接口白得 20+ 方法：findAll/findById/save(INSERT或UPDATE)/deleteById/count/分页
  - save() 按 id 是否为 null 判断 INSERT vs UPDATE
  - JPA 代价：N+1 查询、复杂 SQL 需 @Query/JPQL、SQL 不可见、概念多（实体状态/懒加载/一级缓存）
  - 国内现状：国际/Spring 官方默认 JPA，国内互联网主流 MyBatis(-Plus)；前端类比：JPA≈TypeORM/Prisma，MyBatis≈Knex/手写 SQL
- **澄清"省 SQL"误区**：JPA=简单查询自动生成 SQL、复杂查询要手写（@Query/JPQL/native SQL/Specification-Criteria，且写法别扭、返回 Object[] 无类型）；MyBatis=SQL 从来手写（XML），省的是 JDBC 样板代码，动态 SQL（<where>/<if>/<foreach>）是它强项
  - 结论：JPA 简单时白嫖、复杂时受罪；MyBatis 始终自己写但顺手。项目全是简单 CRUD 单表查询，是 JPA 最舒服场景
- **不用 ORM 会怎样（JDBC 手写演示）**，基于 task_event_log 表 + TaskEventService.saveEvent 实例：
  - 一条 INSERT：JPA 1 行 vs JDBC ~15 行（取连接、PreparedStatement、9 个参数按索引 set、枚举/JSON/时间手动转、SQLException 处理）
  - 一条查询：JPA 1 行方法名 vs JDBC ~25 行（ResultSet 逐行 + 9 个字段手动 getXxx 映射）
  - JDBC 痛点清单：样板代码 70%、列名/类型拼错编译期查不出、受检异常 SQLException、事务手动 commit/rollback、分页语法各数据库不同、无缓存/懒加载
  - 前端类比：JPA≈Prisma/TypeORM、MyBatis≈Knex、JDBC≈手写 fetch+手动解析 JSON+手动拼 DOM
- **JDBC 定义**：Java Database Connectivity，JDK 自带数据库访问标准接口（java.sql 包），本身不干活，由厂商驱动实现（H2/MySQL/PG 各有 Driver）
  - 核心三类：Connection（连接）/ PreparedStatement（预编译 SQL）/ ResultSet（结果集）
  - 换数据库=换 driver-class-name 配置+连接 URL，Java 代码不动（标准接口价值）
  - 前端类比：JDBC≈fetch 标准 API，驱动≈浏览器实现，JPA/MyBatis≈axios 封装层；所有 ORM 底层都绕不开 JDBC
  - "绕不开"含义：JDBC 是 JDK 唯一关系型数据库访问接口，厂商驱动都实现它；换数据库只改 driver-class-name+URL，代码不动。唯一例外=NoSQL（Mongo/Redis 不走 JDBC）。类比：所有前端库最终都调浏览器 fetch，同理所有 Java 数据层框架最终都调 JDBC
  - "绕不开"两层含义（用户已确认理解）：① 写代码时框架代劳，一行 JDBC 不用写（axios 帮你调 fetch 的感觉）；② 运行期/排障时绕不开——SQLException、慢 SQL 日志、连接池配置都在 JDBC 层，出问题要懂它
