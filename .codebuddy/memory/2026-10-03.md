## Nacos 升级兼容性预习（用户提问核实）

- 用户问："升级 Nacos Server 3.0.3 会不会导致 micro-lab（旧版本线）又不适配？"
- **核实结论（官方升级手册 v3.0 客户端兼容表）**：**0.x 不兼容 / 1.x 兼容（v3.2 后停支持）/ 2.x 兼容 / 3.x 兼容**——**micro-lab 的 nacos-client 2.3.2（m2 实证）无需任何改动**。
- 方向辨析（教学点）：上次撞墙 = "**新客户端 → 老服务端**"（3.0.3 client ↔ 2.3.2 server，**无向前兼容**，config 静默空读）；本次 = "**老客户端 → 新服务端**"（2.3.2 client ↔ 3.0.3 server，**服务端主动实现多代协议兼容层**）——服务端向下兼容（一代侍四代）、客户端不能向上。
- 升级现场注意（已并入《虚拟机……》挂账条目）：① 3.x 配置项改名（`server.port`→`nacos.server.main.port`；Docker env 方式未用受影响项）② Server/Console 拆分 + v1 API 默认关闭（社区资料提示，现场确认）③ Derby 数据建议干净重建（配置仅两条）④ 鉴权三变量或需补。
- 彩蛋视角：升级后 = "**双年代客户端同台**"（micro-lab 2.3.2 + backend 3.0.3 同时注册到同一 3.0.3 服务端）——活体兼容性实验。
- 工具记录：官方升级手册 https://nacos.io/docs/v3.0/manual/admin/upgrading/ （客户端兼容表 + 服务端升级来源表 + 配置项改名对照）。
- **用户提炼（本轮确认 + 校准）**：用户总结"服务端可兼容 2.x 客户端，不像三件套那样强绑定"——**校准为：不是"不绑定"，而是"绑定强度不同 + 方向不对称"**：三件套 = **硬绑定**（同进程代码/API 级耦合，必须同升，不配套显式报错）；Nacos C-S = **软绑定（单向兼容）**（协议级，服务端维护兼容窗口：0.x✗ / 1.x✓（v3.2 停）/ 2.x✓ / 3.x✓）。★ 关键警示：**兼容窗口会收缩**（"能跑"≠"永久豁免"）、老客户端吃不到新特性（xDS/MCP 等）、升级节奏权在用户侧（软绑定的最大好处）。
