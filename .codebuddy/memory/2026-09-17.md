## 第 8 站部署排障（重大坑，已修复待验证）
- 现象：micro-lab 三个 Pod 全部 CrashLoopBackOff，日志报 `no main manifest attribute, in /app/app.jar`（jar 无 Main-Class）。
- 根因：micro-lab 父 POM 自建（未继承 spring-boot-starter-parent），pluginManagement 只写了 version、**未定义 repackage execution** → `mvn package` 只产出普通 jar；而本地 `spring-boot:run` 不读 manifest，问题隐身到容器才爆。对照：backend 继承 starter-parent（pom 第 7-12 行）所以从无此问题。
- 修复：micro-lab 父 pom 的 pluginManagement 中显式加 `<executions><execution><id>repackage</id><goals><goal>repackage</goal></goals></execution></executions>`（已改好）。
- 待执行：重新 package（验证 .jar.original 出现 + java -jar 可跑）→ 重建 3 镜像 → 重传双节点 → 两台 ctr import 覆盖 → `kubectl rollout restart` 三个 deployment → curl 30090 验证。
- 环境备注：镜像已成功导入 node1/node2；两节点 IP 未漂（node1=.128、node2=.129）。
