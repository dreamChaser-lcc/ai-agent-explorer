## 二、Q1 完整答案：`NULL` 是什么意思

**一句话**：写在列定义末尾的 `NULL` 是**列约束**——声明"这一列允许不填值"。

**前端类比**：表单的 `required` 属性反着用：

```jsx
<input name="taskNo" required />   {/* NOT NULL：必填，空着不让提交 */}
<input name="createdBy" />          {/* NULL：选填，不填就是 null */}
```

**三兄弟对比**：

| 写法 | 人话 | 不填会怎样 |
|---|---|---|
| `NOT NULL` | 必填 | 数据库报错，整条 INSERT 失败 |
| `NULL`（或不写） | 选填 | 允许插入，这格存 NULL |
| `NOT NULL DEFAULT 0` | 必填但有兜底 | 不填自动补默认值 |

> 小知识：SQL 里不写约束时**默认就允许 NULL**，显式写 `NULL` 是"自我文档化"（告诉读表结构的人：这里故意设计成可空）。

**关键坑：NULL 不是 `''` 也不是 `0`**

| 值 | 含义 | 类比 |
|---|---|---|
| `''` 空字符串 | 有一个值，值是空的 | 问卷答了这题，但答案是空白 |
| `0` | 有一个值，值是零 | 问卷答了"0" |
| `NULL` | **压根没有值** | 这题根本没答 |

判断必须用 `IS NULL` / `IS NOT NULL`——`WHERE x = NULL` **永远查不到任何行**（`NULL = NULL` 的结果是"未知"，不是 true）。

**本项目为什么这么多 NULL**：规律是"**系统必定能给的 → NOT NULL；业务上还没发生/可能没有的 → NULL**"：

| 列 | 为什么可空 |
|---|---|
| `current_step_id` | 任务还没开始执行 |
| `error_message` | 任务还没失败过（S3 实测：15 行全 NULL → `COUNT(error_message) = 0`） |
| `started_at` / `completed_at` | 还没开始/没完成 |
| `created_by` | 可空，但实际被后端硬编码填成 `'demo-user'`——**"可空" ≠ "一定空"**（S3 侦探实录） |

**唯一索引与 NULL 的关系**：`uq_research_task_idempotency_key` 是唯一索引，但**允许多个 NULL 共存**（不冲突）——这是场景④幂等键设计的基石：不带幂等键的老请求互不影响，带相同键的才被拦。

**工程口诀**：能不 NULL 就不 NULL，该 NULL 的才 NULL（约束越严，数据越干净）。

## 三、Q2 完整答案：`TIMESTAMP WITH TIME ZONE` 是什么意思

**一句话**：存"**绝对时间点 + 时区**"的时间戳类型——同一瞬间在全球只有一个确定值。

**前端类比**：JS 的 `Date` 对象 / ISO 8601 字符串：

```js
new Date().toISOString()
// "2026-10-15T02:30:00.000Z"  ← Z = UTC，一个绝对瞬间
```

`Date` 对象内部存的是 UTC 毫秒数（绝对瞬间），显示时按本地时区格式化成你要的样子——数据库的 `TIMESTAMP WITH TIME ZONE` 就是这个思路。

**带时区 vs 不带时区**：

| SQL 类型 | 类比 | 存的是什么 |
|---|---|---|
| `TIMESTAMP` | 一张写着 `10:30` 的纸条 | 墙上时间——不知道是北京 10:30 还是伦敦 10:30 |
| `TIMESTAMP WITH TIME ZONE` | `Date` 对象 / `2026-10-15T10:30:00+08:00` | 绝对瞬间 + 时区偏移，全球唯一确定 |

**为什么项目所有时间列都用它**：Java 侧实体字段是 `OffsetDateTime`（如 `ResearchTask.startedAt`），JDBC 正好映射；多时区部署、跨机器对比时间都不会乱。

**时区指纹（场景⑦ 亲眼见过）**：同一个时间点的两种写法——

- 直查数据库：`2026-10-11T16:30:00+08:00`（Java `OffsetDateTime` 原生格式）
- 走 Redis 缓存后：`2026-10-11T08:30:00Z`（Jackson 序列化成 JSON 的 UTC 格式）

**`16:30+08:00` 与 `08:30Z` 是同一个瞬间**——存的是绝对时间，显示格式不同。当时就是靠这个差异证明"命中了缓存"。

**为什么 `created_at` 是 NOT NULL**：INSERT 那一刻时间就确定了，业务上不可能"还没发生"——所以必填；反之 `started_at`/`completed_at` 是"还没发生"的可空列。
