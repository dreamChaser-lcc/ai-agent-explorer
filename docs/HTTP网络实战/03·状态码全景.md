## 一、五大家族

| 段 | 语义 | 常见 |
|---|---|---|
| **1xx** | 协议中间态 | 101（升级 WebSocket） |
| **2xx** | 成功 | 200 / **201 创建** / 202 接受（异步） |
| **3xx** | 重定向 | 301 永久 / 302 临时 / **304 缓存命中** |
| **4xx** | **你的错**（客户端） | 400 / 401 / 403 / **404** / 409 / 429 |
| **5xx** | **我的错**（服务端） | 500 / 502 / 503 / 504 |

## 二、项目 ApiExceptionHandler 的状态码哲学

```text
400 BAD_REQUEST       ← 参数校验失败 / DataAccessException 根兜底
401 UNAUTHORIZED      ← TokenAuthFilter 令牌缺失/错误
404 NOT_FOUND         ← TaskNotFoundException → "资源不存在"
409 CONFLICT          ← 乐观锁冲突（OptimisticLockingFailure）
                        / 唯一索引撞（DataIntegrityViolation）
                        ——语义："冲突了，刷新重试，别原样重发"
500 INTERNAL_ERROR    ← 兜底（未知异常，两边的"最后的墙"）

★ 状态码是【给调用方/前端的语义信号】，不是随便选的：
  4xx = 你改了可能好；5xx = 你别折腾了等我们修
```

## 三、409 的一生（把 [J4 异常体系](../Java基础实战/J4·异常体系.md) [网页版](https://github.com/dreamChaser-lcc/ai-agent-explorer/blob/main/docs/Java基础实战/J4·异常体系.md) 的链路串一遍）

```text
并发确认 → @Version 乐观锁冲突
→ Hibernate StaleObjectStateException
→ @Repository 翻译成 OptimisticLockingFailureException
→ ApiExceptionHandler @ExceptionHandler 捕获
→ 返回 409 + {"code":"CONCURRENT_CONFLICT","message":"请刷新后重试"}
→ 前端看到 409 = 知道该刷新而不是报障
（一个状态码背后是整条异常翻译流水线——J4 全课的现场）
```

## 四、易混三对

```text
401 vs 403：没登录(你是谁？) vs 登录了但没权限(你不能)
404 vs 400：路径资源不存在 vs 请求本身烂（体/参数非法）
502 vs 504：网关收到【错误响应】（上游炸了） vs 网关【没等到响应】（上游超时）
——Nginx/K8s Ingress 排障时的第一分诊
```

## 面试速答

```text
Q：为什么 409 不用 400？ A：400 表示"请求烂"；409 表示"请求对但状态冲突"，
   语义精确才能指导前端行为（重试 vs 修改）。
Q：幂等重试返回什么？ A：首次 201、重放也返回 200/201 带【首次的结果】。
```

## 一句话

```text
状态码 = 机器可读的语义：4xx 你改、5xx 我修、409 刷新重试。
项目 409 的背后是 J4 异常翻译的完整流水线。
```
