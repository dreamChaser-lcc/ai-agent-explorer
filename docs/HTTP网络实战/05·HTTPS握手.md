# 05 · HTTPS 握手——对称 + 非对称的分工

> **状态**：⬜ 未学习 ｜ **下一课**：06·从 URL 到响应

## 一、两种加密的分工（核心思想）

```text
非对称加密（公钥/私钥）：安全但【慢】（比对称慢 100~1000 倍）
对称加密（一把钥匙）：快，但"钥匙怎么安全给对方"是死结

HTTPS 的答案：非对称【只干一件事——交换对称钥匙】，
之后全程用对称加密跑业务——各取所长
```

## 二、TLS 1.2 握手四步（简化版）

```text
① Client Hello：我支持这些加密套件 + 随机数 A
② Server Hello：选这套 + 随机数 B + 【证书】（含公钥）
③ 客户端验证证书（CA 链向上找到系统信任的根）
   → 生成预主密钥，用【服务器公钥】加密发过去
④ 双方用 随机数A + 随机数B + 预主密钥 算出对称密钥 → 握手完成
之后：应用数据全走对称加密
```

## 三、证书在防什么（中间人攻击）

```text
没有证书的世界：你连的"银行"可能是中间人伪装的
证书 = 【CA 用私钥签的"这家服务器是它"担保书】
浏览器内置 CA 根证书 → 验签通过 = 确认公钥真的属于目标服务器
→ 中间人换不掉公钥（它没有 CA 私钥）→ 钥匙交换安全 → 后面全安全
```

## 四、和项目的两个关联

```text
① localhost 开发的 http://——为什么浏览器不报警？
   http 明文跑本地没问题；生产必须 https（外网明文=裸奔）
② 自签证书（公司内网）：
   浏览器警告 = 这个证书的 CA 不在信任列表（技术上加密没问题，
   只是"没人担保"）——与 Nacos/内网服务常配的 self-signed 同理
```

## 面试速答

```text
Q：为什么不全用非对称？ A：慢百倍——非对称只用于交换钥匙，业务用对称。
Q：证书防什么？ A：中间人——CA 担保公钥归属，换不掉就解不开。
Q：TLS 握手几次 RTT？ A：1.2 需 2 次（4 个消息）；1.3 压到 1 次（更快）。
```

## 一句话

```text
HTTPS = 非对称换钥匙（防中间人）+ 对称跑数据（要快）。
证书是 CA 的担保书——验的是"这把公钥真的是它的"。
```
