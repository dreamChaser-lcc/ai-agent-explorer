## 一、为什么要开这条线

2026-10-24 对照 live-java 规范后发现是**两套时代的架构**：

| | 本项目 | 规范 |
|---|---|---|
| 版本基线 | Java 21 / Boot 3.5（`jakarta.*`） | Java 11 / Boot 2.x（`javax.*`） |
| 形态 | **单体** | **Spring Cloud 微服务**（Nacos/Feign） |
| 持久层 | **JPA + 1 个数据源** | **MyBatis-Plus + 15 个数据源**（`@DS`） |
| 事务策略 | **`@Transactional` 22 处**（强一致） | **禁止业务方法加事务**（多数据源下失效） |
| 中间件 | 手写锁 / `@Scheduled` / 单 Kafka | Redisson / XXL-Job / 7 集群 |
| 工程工具 | 无 Lombok/MapStruct/Knife4j | 全都有 |
| 测试/容器/可观测 | ✅ 有 | ❌ 规范未涉及（**我们的领先项**） |

**本线只学"能提升工程能力"的部分**——不学版本降级项（Java 11 / Boot 2.x）。

**判断依据**：中间件选型 = f(规模)。单实例下 XXL-Job 是过度设计；多实例下 `@Scheduled` 是事故源。**学的是"什么信号出现时该换什么"**，不是照抄。

## 二、课程地图（四期 15 课）

### 一期：工程工具（5 课 · 1~2 周 · 每天 1 小时）

> 目标：低成本高收益，把项目"看起来像企业项目"。

| # | 专题 | 核心知识点 | 估时 |
|---|---|---|---|
| **T1** | **Lombok** | `@Slf4j`/`@Data`/`@RequiredArgsConstructor`；**编译期注解处理器**（非运行时反射） | 1 天 |
| **T2** | **MapStruct** | **编译期生成实现类** vs `BeanUtils` 反射；`@Mapping` 字段名不一致 | 1 天 |
| **T3** | **API 文档自动生成** | [SpringDoc OpenAPI 3](T3·API文档自动生成.md)（**Knife4j 在 Boot 3.5 有版本坑，实测后改用官方 springdoc**）；`@Tag`/`@Operation`；生产关闭 | 2 小时 |
| **T4** | **ErrorEnum** | 错误码设计（模块码+序号）；`BusinessException` 与全局处理配合 | 半天 |
| **T5** | **Redis Key 常量化** | `RedisConstant`；`xxx:${type}:${userId}` 命名规范 | 1 小时 |

### 二期：中间件进阶（4 课 · 2~3 周）

> 目标：把"手写过/够用"的升级成"生产级方案"。

| # | 专题 | 核心知识点 | 估时 |
|---|---|---|---|
| **T6** | **Caffeine 本地缓存** | W-TinyLFU 算法；`LoadingCache`；**多层缓存**（Caffeine→Redis→DB）；多实例脏读难题 | 2 天 |
| **T7** | **Redisson 分布式锁** | **看门狗续期**；可重入（Hash+计数）；公平锁/读写锁；与手写锁能力对比 | 2 天 |
| **T8** | **Kafka 生产级** | `autoStartup` 运行时启停；`batchListener` 批量消费；多集群；**重试与死信队列** | 1 天 |
| **T9** | **XXL-Job** | 调度中心+执行器架构；**分片广播**；失败重试告警；阻塞策略 | 3 天 |

### 三期：架构升级（4 课 · 4~6 周）

> 目标：理解"多数据源 + 微服务"的架构约束。

| # | 专题 | 核心知识点 | 估时 |
|---|---|---|---|
| **T10** | **MyBatis-Plus** | `BaseMapper` 通用 CRUD 原理（MappedStatement 动态注入）；`lambdaQuery`；与 JPA 逐项对比 | 5 天 |
| **T11** | **@DS 多数据源** | `AbstractRoutingDataSource` 路由；**事务内切库失效**；`REQUIRES_NEW`；异步上下文丢失 | 3 天 |
| **T12** | **Nacos + OpenFeign** | 注册中心 vs 配置中心；配置热更新；Feign 动态代理 + LoadBalancer；超时重试熔断 | 1 周 |
| **T13** | **微服务工程** | 分布式事务（Saga/TCC/本地消息表）；链路追踪 traceId 透传；灰度发布 | 1 周 |

### 四期：业务域（2 课 · 按需）

| # | 专题 | 核心知识点 | 估时 |
|---|---|---|---|
| **T14** | **COS 对象存储** | 直传 vs 服务端中转；签名 URL；分片上传 | 2 天 |
| **T15** | **EasyExcel** | 流式读写不 OOM；与 POI 内存对比；大数据导出 | 2 天 |

## 三、每课的五步闭环（沿用场景线）

```text
① 设计/审计：对照规范原文 + 本项目现状，说清"为什么有这个差异"
② 编码：**在本项目做最小 demo**（放 demo 包，不动现有业务代码）
③ 验证：给实测数据（延迟/体积/代码量/SQL 条数…），不空讲
④ 文档：讲义落档 + 问答记录（双台账）+ 能力对比表
⑤ 提交：**等学员明确发话**（"下一课"= 先提交上一课）
```

## 四、学习约定（沿用 + 本线新增）

**沿用的 4 条**（来自 Spring/场景线）：

1. **提问必落档**：全局提问索引 + 每课自带「本课问答记录」；
2. **会话内容完整落档**：代码块/对比表/口诀不许压缩成摘要；
3. **涉数据库以 SQL 视角为主**：JPA 必附"底层生成的 SQL"；
4. **引用旧知识必须可回溯**：带链接 + 前置知识速查节。

**本线新增的 4 条**：

5. **每个专题必给「能力对比表」**：三列——本项目现状 / 规范方案 / 第三方案（如 MyBatis 对比 JPA）；
6. **每课结尾必列 2~3 道验收题**：答不出来 = 没学透；
7. **不学版本降级项**：Java 11 / Boot 2.x 只了解差异（迁移时看官方指南），不投入时间；
8. **★ 文件清单/代码引用必须双链接，且写完必须校验**（2026-10-25 学员纠正"文件清单不能 Ctrl 点击跳转"），写法示例：

[`OpenApiConfiguration.java`](../../backend/src/main/java/com/aiexplorer/researchagent/infrastructure/config/OpenApiConfiguration.java) [网页版](https://github.com/dreamChaser-lcc/ai-agent-explorer/blob/main/backend/src/main/java/com/aiexplorer/researchagent/infrastructure/config/OpenApiConfiguration.java)

- **禁止**行内代码写路径（`` `backend/...` `` 不可点击）；
- **禁止** `backend/...` 缩写（必须完整相对路径，否则链接失效）；
- 写完用脚本校验：**断链 = 0 且「缺网页版」= 0**。
