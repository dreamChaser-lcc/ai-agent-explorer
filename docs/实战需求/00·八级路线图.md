# 实战需求 · 八级路线图（标签域 Tag，从 CRUD 到架构）

> **设计原则**：在现有 research-agent 项目内**新建"标签域"**，从最小 CRUD 渐进到架构化；
> 每级聚焦 2–3 条知识线，逐级评审，前期快后期深。
> **技术选型**：MyBatis + H2（lite）/ PG（docker）；不新建项目。
> **交付**：代码 + 测试 + 验证记录（三件套）。
> **评审**：混合——你自查为默认；**L4（幂等/并发）与 L6（MQ）由我复核**。

---

## 一、八级路线图

| 级 | 主题 | 新建内容 | 覆盖知识线 | 工时 | 验证 |
|---|---|---|---|---|---|
| **L1** | 标签域最小 CRUD | `tag` 表 + 5 接口 + 参数校验 + 统一错误码 | SQL/DDL · SP3(MVC) · SP11(分层) | 0.5 天 | 测试 + 实测 |
| **L2** | 分层重构 | Controller/Service/Repository + DTO/VO + 事务边界 | 分层命名 · 事务传播(SP4) | 0.5 天 | 测试 + 实测 |
| **L3** | 查询增强 | 分页/排序/多条件 + **任务-标签多对多 JOIN** + 索引 | SQL(JOIN/分页) · MySQL(索引/执行计划) | 1 天 | 测试 + 实测 |
| **L4** | 幂等与并发 | 创建幂等（唯一约束+幂等键）+ 乐观锁 + 分布式锁 | 场景⑨ · Redis 05/09 · 并发 | 1 天 | **我复核** |
| **L5** | 缓存 | @Cacheable + 缓存三件套 + 失效策略 + TTL | Redis 04/06 · SB 缓存抽象 | 1 天 | 测试 + 实测 |
| **L6** | 事件与 MQ | 标签变更事件 → Kafka + 幂等消费 + DLT | M4/M5/M6 · 场景⑥ | 1.5 天 | **我复核** |
| **L7** | 可观测 | 业务指标 + 健康探针 + 慢接口监控 | SB5/SB8 | 1 天 | 测试 + 实测 |
| **L8** | 架构化 | 模块化或 Starter 抽取 + API 文档 + 压测报告 | SB2 · 服务架构 | 2 天 | 评审 |

```text
知识线覆盖检查（全部 12 条）：
  SQL/MySQL      → L1(DDL) L3(JOIN/索引/执行计划) L4(唯一约束)
  Java/数据结构   → L3(分页排序) L4(并发) L5(缓存结构)
  Spring         → L2(分层/事务) L5(@Cacheable)
  Spring Boot    → L7(指标/探针) L8(Starter/模块化)
  MQ             → L6(事件/幂等/DLT)
  Redis          → L4(分布式锁) L5(缓存)
  HTTP           → L1(RESTful/状态码) L8(API 文档)
  ES             → L3 延伸（标签搜索，选做）
  设计模式        → L2(策略/模板方法) L6(观察者/事件)
  技术栈补齐      → L8(模块化/Starter 封装)
  业务场景        → 全程（对照场景②③④⑥⑨）
  服务架构        → L8(分层架构/依赖倒置)
```

## 二、验证记录模板（每级都要交）

```markdown
## L{N} 验证记录

### 1. 启动
- 命令：.\start.ps1（lite）+ 关键日志行（Started / 表创建 / 指标注册）

### 2. 接口实测（curl 输出原文）
- 成功路径：...
- 失败路径（每个错误码一条）：...

### 3. 测试
- mvn test 输出（Tests run: X, Failures: 0）

### 4. 自评
- 本级的 3 个难点是什么 / 卡了多久 / 参考了哪个现有文件
```

## 三、评审规则（混合）

```text
默认（L1/L2/L3/L5/L7/L8）：你按验收标准自查 + 交验证记录 → 我抽查代码（随机 2 行让你解释）
强制复核（L4/L6）：我必须跑命令验证（幂等/漏消息/锁的行为），不通过不进入下一级
```

---

## 四、约束（全程有效）

```text
① 不新建 maven 项目（在 backend 内加包）
② 不破坏现有测试（每级结束 mvn test 全绿）
③ 不引入新的重量级依赖（需要时先问）
④ 允许参考现有代码（SP11/场景②③），但评审会抽问"为什么这样写"
⑤ 每级只做本级要求，不提前实现后面的（避免"一步到位"失去渐进意义）
```
