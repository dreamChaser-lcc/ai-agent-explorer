# MQ 消息队列实战（Kafka + RabbitMQ）课程总纲

> **目标**：掌握消息队列的通用概念与两大主流实现（Kafka / RabbitMQ），
> 能回答"丢失/重复/顺序/积压"四大可靠性问题，能做选型决策。
> **状态图例**：⬜ 未开始 ｜ 🔵 进行中 ｜ ✅ 完成
> **已有基础**：场景⑥（Kafka 实战体验：消息链路 / 消费幂等 / 10ms 守卫）→ 本课补齐体系

## 一、为什么学 MQ（你已经摸过一次）

```text
场景⑥ 已经用过 Kafka：任务异步化（HTTP 同步等待 → 消息化）
  踩过/解过：消费幂等（10ms 守卫秒拦重复消息）、消息链路铁证、重放 1→0
但当时是"会用"——本专题要回答：
  消息会不会丢？会不会重复？顺序怎么保证？积压了怎么办？
  Kafka 和 RabbitMQ 到底差在哪、什么时候选谁？
```

## 三、学习路线（三阶段，渐进式——呼应 start.ps1 的"按需开依赖"）

```text
阶段 1：概念 + Kafka 基础（项目已有 Kafka，趁热）
  M1 → M3
  环境：.\start.ps1 -Mode kafka（已有；本机无 Kafka 时用 Docker）

  M2 → M5
  环境：Docker 起 rabbitmq:3.13-management（15672 管理界面）

  M4 → M6 → M7
  环境：同阶段 1/2；实验会故意制造丢消息/重复/积压
```

## 七、一句话

```text
消息队列 = 把"函数调用"变成"投递信件"：
  发信的不等回信（异步）、收信的各取所需（解耦）、高峰先进信箱（削峰）。
Kafka = 高吞吐的"日志流水账"；RabbitMQ = 灵活路由的"邮局"。
学完这条线，你能回答四大可靠性问题 + 知道什么时候该用谁。
```
