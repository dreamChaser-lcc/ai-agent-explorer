# MQ 术语表（Kafka / RabbitMQ 通用，持续补充）

> 遇到不懂的词先查这里。每个词给：**字面 → 含义 → 类比 → 项目里的样子**。

## LAG（滞后量 / 积压条数）

```text
字面：lag = 落后、滞后
含义：消费者落后于生产者多少条消息没处理
公式：LAG = LOG-END-OFFSET（最新位置）− CURRENT-OFFSET（已消费位置）
类比：食堂打饭——锅里 100 份，你打到第 30 份，LAG = 70
项目实测（M3）：PARTITION 2  CURRENT=1 / LOG-END=1 → LAG=0（无积压）
★ LAG 是消费者健康的核心指标：持续涨=跟不上；涨且 CONSUMER-ID="- "=没消费者
```

## retention（保留期 / 保留策略）

```text
字面：retention = 保留、保存（"记住多久"）
含义：Kafka 消息在磁盘上保留多久，到期删除——【与是否被消费无关】
配置：retention.ms（默认 7 天）/ retention.bytes（按大小）
类比：监控录像保留 7 天——看过没看过不影响它何时被覆盖
项目：未显式配置 → 默认 7 天 → 期间可 --from-beginning 重放
★ 消费只是移动 offset 书签，不删消息；超过 retention 才真的丢
```

## SLA（服务等级协议）

```text
字面：Service Level Agreement = 服务等级协议（对外承诺）
含义：承诺的服务质量指标（可用性 99.9% / P99 延迟 / 消息投递延迟）
类比：外卖"30 分钟必达"，超时赔付
MQ 语境："消息从生产到被处理 ≤ 60 秒"
★ 关系：LAG 是手段指标（过程），SLA 是结果承诺（对用户）——LAG 涨 → 延迟超 SLA → 违约
```

## segment（日志段 / 分段文件）

```text
字面：segment = 段、片段
含义：一个 Partition 在磁盘上切成多个段文件（默认 1GB/段）
三件套（同前缀命名，起始 offset）：
  xxx.log（消息体，追加写）/ xxx.index（offset→位置稀疏索引）/ xxx.timeindex（时间索引）
类比：厚书分册——查目录（index）定位册页，再翻正文（log）
为什么分段：① 删旧数据=删整个段文件 ② 稀疏索引省空间 ③ 顺序写友好（高吞吐）
项目：/var/lib/kafka/data/research-task-execution-0/00000000000000000000.log（消息量小仍在第 0 段）
```

## 四个词怎么协作

```text
消息写进 segment（分段日志）→ 消费者读并提交 offset（书签）
  → 落后量 = LAG（健康指标）→ 到期 = retention 删除（不看消费）
  → LAG 涨到延迟超承诺 = SLA 违约（告警）
```
