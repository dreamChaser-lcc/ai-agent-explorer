## 一、五原则一句话版

| 原则 | 一句话 | 违反的味道 |
|---|---|---|
| **S** 单一职责 | 一个类只一个"变化原因" | 类名里带 And |
| **O** 开闭 | 加功能用"加"，不用"改" | 加一个枚举值要改五处 if |
| **L** 里氏替换 | 子类必须能无感替父类 | 子类抛父类没有的异常/改语义 |
| **I** 接口隔离 | 接口小而专，不逼实现方实现废方法 | 实现类里一堆空方法 |
| **D** 依赖倒置 | 依赖接口不依赖具体 | new 具体类满天飞 |

## 二、项目体检（拿真实代码对号）

```text
✅ O 开闭：ExecutionMode 加新模式 → 新增 Strategy 类即可（03 课）
✅ D 依赖倒置：Service 依赖 JpaRepository / LlmClient 接口（配置注入哪个实现）
✅ L 里氏：JpaTaskEventLogStore / MyBatisTaskEventLogStore 同接口可互换（@DS 思想）
⚠️ S 单一：Controller 里写业务逻辑的味道——发现自己想在 Controller 里查库就警觉
⚠️ I 接口：JpaRepository 间接继承一大串接口（Crud+ListPaging+...）
   ——但这是框架的选择，业务代码里自己定义接口时保持小
```

## 三、一个万能自检法

```text
改需求时问三句：
  ① 我是在【加】新代码还是在【改】老代码？（开闭）
  ② 影响范围有没有超出这个类的"变化原因"？（单一职责）
  ③ 调用方需要知道我是"哪个具体实现"吗？（依赖倒置）
三句都绿 → 结构健康；两句红 → 重构信号。
```

## 四、面试速答

```text
Q：SOLID 里哪个最重要？
A：开闭——它是其余四条的"果"：职责单一才可能只加不改，
   依赖倒置才可能注入新实现。答的时候举例（策略模式）。
Q：设计模式的本质？
A：把"变"和"不变"分开——模板方法圈住不变流程、策略外置可变算法、
   代理隔离横切增强、责任链编排处理序列。
```

## 五、一句话（全目录收官）

```text
SOLID 是目的，模式是手段：
"把变与不变分开"——所有 8 课模式都是这句话的变奏。
```
