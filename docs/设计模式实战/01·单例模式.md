# 01 · 单例模式（Singleton）

> **状态**：⬜ 未学习 ｜ **下一课**：02·工厂与建造者

---

## 一、是什么

```text
一个类全应用只允许一个实例 + 全局共享一个访问点。

三个要素：
  ① 私有构造器（堵死 new）
  ② 自己持有唯一实例
  ③ 静态方法对外提供
```

## 二、四种写法（从土到最佳）

```java
// ① 饿汉式：类加载即创建（简单，可能浪费）
private static final Singleton INSTANCE = new Singleton();

// ② 懒汉式双重检查锁（DCL）——面试考点，容易写错
private static volatile Singleton instance;   // volatile 防 亂序！
public static Singleton get() {
    if (instance == null) {
        synchronized (Singleton.class) {
            if (instance == null) instance = new Singleton();
        }
    }
    return instance;
}

// ③ 静态内部类（JVM 类加载机制保证线程安全，懒加载）
private static class Holder { static final Singleton I = new Singleton(); }

// ④ 枚举——《Effective Java》最佳：防反射攻击 + 防序列化克隆
public enum ConfigHolder { INSTANCE; }
```

## 三、项目活例

| 例子 | 说明 |
|---|---|
| **Spring bean 默认单例** | @Component 家族全是 singleton（SP1 bean 作用域） |
| 枚举单例 | J6 §7.2：枚举常量天然单例，防反射防序列化 |

**Spring 单例 vs 手写单例的区别**：Spring 是"容器管理的单例"（每个容器一个），
手写是"类加载器级别的单例"——工程上用 Spring 的就够了。

## 四、面试速答

```text
Q：DCL 为什么要 volatile？
A：new 不是原子的（分配→初始化→赋引用），重排序可能让别的线程拿到"半成品"。
Q：为什么枚举是最佳？
A：JVM 禁止反射 new 枚举；序列化走 valueOf 不产生新实例。
```

## 一句话

```text
工程里 99% 的单例交给 Spring 容器；
手写时用枚举（防反射防序列化）或静态内部类（懒加载）。
```
