# 03 · 策略模式（Strategy）

> **状态**：⬜ 未学习 ｜ **下一课**：04·模板方法

---

## 一、是什么：消灭 if-else 分支地狱

```java
// 反面教材：加一种模式就要改这里（违反开闭原则）
public String execute(String mode) {
    if ("SYNC".equals(mode)) return runSync();
    else if ("ASYNC".equals(mode)) return runAsync();
    else throw new IllegalArgumentException();
}

// 策略：每种做法一个类，统一接口，运行时挑
public interface ExecutionStrategy { Result execute(Task task); }
public class SyncExecution implements ExecutionStrategy { ... }
public class AsyncExecution implements ExecutionStrategy { ... }  // Kafka 版

// 使用：map 一查，不认识新分支也不报错
Map<ExecutionMode, ExecutionStrategy> strategies;   // Spring 注入全部实现
strategies.get(task.mode()).execute(task);
```

**价值**：新增行为 = 加一个类，不改老代码（开闭原则的实践）。

## 二、项目活例

| 例子 | 策略维度 |
|---|---|
| **ExecutionMode（SYNC/ASYNC）** | 同步直跑 vs Kafka 异步——项目最典型的策略分叉 |
| `LLM_CLIENT_IMPL`（http / langchain4j） | 两个 LlmClient 实现按配置切换 |
| Spring `HandlerMethodArgumentResolver` | 按参数类型挑解析器 |
| HashMap 的 `Comparator` 参数 | 排序策略外置（TreeMap 构造器传入） |

## 三、识别信号（什么时候该用策略）

```text
① 同一个动作有多套"做法"，按【枚举/类型】分叉
② if-else 里的每个分支都是完整逻辑（不是一两行）
③ 未来可能加第三种做法
三占二 → 用策略。
```

## 四、Spring 的"策略自动收集"技巧

```java
@Component
public class StrategyRegistry {
    private final Map<ExecutionMode, ExecutionStrategy> map = new EnumMap<>(ExecutionMode.class);

    // ★ 构造器注入【全部实现】——加新策略类自动被收集，零注册代码
    public StrategyRegistry(List<ExecutionStrategy> all) {
        all.forEach(s -> map.put(s.supportMode(), s));
    }
}
```

## 五、面试速答

```text
Q：策略模式和 if-else 的取舍？
A：分支稳定且少（2 个、不会加）用 if-else；会增、逻辑长用策略。
Q：怎么避免"每加策略改注册处"？
A：Spring 注入 List<接口> 自动收集 + 每个实现自带 key。
```

## 一句话

```text
策略 = 把"每种做法"封装成类，用 Map<枚举,策略> 查表分发。
Spring 注入 List<接口> 自动收集——加策略只加类、零改老代码。
```
