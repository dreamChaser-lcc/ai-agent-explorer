# 02 · 工厂与建造者模式

> **状态**：⬜ 未学习 ｜ **下一课**：03·策略模式

---

## 一、工厂：把 new 藏起来

```java
// 不用工厂：调用方背着具体类型
LlmClient c = new HttpClientImpl(config, proxy);

// 工厂：调用方只要"能力"（接口），怎么造是我的事
public interface LlmClientFactory {
    LlmClient create(LlmProperties props);   // ← 内部决定造哪种
}
```

**价值**：调用方与具体实现解耦——换实现只改工厂，不改调用方。

## 二、项目活例

| 例子 | 模式变体 |
|---|---|
| `LlmClientConfiguration` 按 `APP_LLM_CLIENT_IMPL` 造不同客户端 | **条件工厂**（@Bean 方法当工厂） |
| Spring `ApplicationContext.getBean()` | 容器本身就是超级工厂 |
| ` LoggerFactory.getLogger(X.class)` | 静态工厂方法 |
| Spring Data `RepositoryFactoryBean` | 工厂 Bean（动态生成 Repository 代理） |

## 三、建造者：多参数对象的优雅组装

```java
// 灾难：4+ 个参数的构造器，谁记得住顺序？
new ApiError("T", "m", "p", null, OffsetDateTime.now(), List.of());

// 建造者：可读 + 可选参数
ApiError.builder()
    .code("TASK_NOT_FOUND")
    .message("任务不存在")
    .path("/api/tasks/xx")
    .build();
```

**什么时候用**：参数 ≥4 或可选参数多（构造器重载爆炸时）。

## 四、项目活例

| 例子 | 说明 |
|---|---|
| Lombok `@Builder` | 一行注解生成建造者 |
| Spring Security 的 `HttpSecurity` | 流式建造安全配置链 |
| `StringBuilder` | 最朴素的建造者（字符串增量组装） |

## 五、面试速答

```text
Q：简单工厂 / 工厂方法 / 抽象工厂？
A：一个工厂方法造一个产品=工厂方法；造一族相关产品=抽象工厂；
   用 if-else 分发的=简单工厂（最常用，严格说不是 GoF）。
Q：Builder 和 Factory 区别？
A：Factory 造"哪个"；Builder 管"怎么一步步组装复杂对象"。
```

## 一句话

```text
工厂藏 new（换实现不改调用方），建造者管组装（多参数优雅化）。
Spring 容器 = 全项目的超级工厂 + @Builder = 最常用的建造者。
```
