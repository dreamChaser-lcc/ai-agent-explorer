# 04 · 模板方法模式（Template Method）

> **状态**：⬜ 未学习 ｜ **下一课**：05·代理模式

---

## 一、是什么：父类定骨架，子类填空

```java
public abstract class AbstractParser {
    // ★ 模板方法：final 锁死流程
    public final ParseResult parse(String raw) {
        preCheck(raw);                    // 1. 公共步骤（父类实现）
        String data = doParse(raw);      // 2. 差异点（抽象 → 子类填空）
        return build(data);              // 3. 公共步骤
    }
    private void preCheck(String raw) { if (raw == null) throw ...; }
    protected abstract String doParse(String raw);   // ← 空位
    private ParseResult build(String d) { ... }
}
```

**价值**：流程只有一份（不会每个子类写歪），变化点被圈定。

## 二、与策略的对比（最容易混的一对）

| | 模板方法 | 策略 |
|---|---|---|
| 差异粒度 | 流程中的【某一步】 | 【整一套做法】 |
| 结构 | 继承（is-a 骨架） | 组合（has-a 算法） |
| 例子 | 解析流程固定、格式不同 | 同步/异步两种执行 |

## 三、项目活例

| 例子 | 说明 |
|---|---|
| `BaseTimeEntity` | 骨架共享：createdAt/updatedAt 字段——模板思想的"数据版" |
| **JdbcTemplate** | execute 流程（拿连接/执行/翻译异常/归还）固定，SQL 与 RowMapper 是填空位 |
| `AbstractRoutingDataSource` | 路由骨架固定，路由键子类给 |
| JUnit/AOP 环绕 | @Around：proceed 前后框架围好了，逻辑你填——广义模板 |

## 四、面试速答

```text
Q：模板方法和策略怎么选？
A：只变"其中一步" → 模板方法（继承）；整套算法都换 → 策略（组合）。
Q：为什么模板方法是组合优于继承的反例？
A：它就是"继承用得其所"的场景——流程强约束时，继承反而是最直白的表达。
```

## 一句话

```text
模板方法 = 父类 final 锁流程，子类填空位。
JdbcTemplate 是最常被忽略的活例子：框架锁"连接/异常翻译"流程，你填"SQL + 映射"。
```
