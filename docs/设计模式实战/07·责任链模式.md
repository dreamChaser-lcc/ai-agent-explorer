# 07 · 责任链模式（Chain of Responsibility）

> **状态**：⬜ 未学习 ｜ **下一课**：08·SOLID 收网

## 一、是什么：请求沿着"流水线"过安检

```text
请求 → [Filter1] → [Filter2] → [Filter3] → [Interceptor] → [Controller]
        逐个过：每个节点可以【放行 / 拦下 / 改行李】
        谁处理完谁说了算，后面的人可能根本看不到请求

结构三要素：
  ① 每个节点实现同一接口（doFilter）
  ② 节点持有下家的引用（chain.doFilter 继续 / 不调 = 拦截）
  ③ 顺序由装配者决定（@Order / registration 顺序）
```

## 二、与策略的对比（一对好辨析）

| | 责任链 | 策略 |
|---|---|---|
| 节点关系 | 一条线【串行】都过一遍 | Map【查表】命中一个 |
| 语义 | 每层各做各的事 | 互斥的多套做法 |
| 例子 | Filter 链 | SYNC/ASYNC |

## 三、项目活例

| 例子 | 说明 |
|---|---|
| **Filter 链** | TokenAuthFilter(1) → BodyCachingFilter(2) → Controller（SP8 实操过 @Order） |
| **Interceptor** | RequestTraceInterceptor——Filter 之后、Controller 之前 |
| Spring Security | `HttpSecurity` 配的就是一条安全责任链 |
| **Netty Pipeline** | 网络框架的经典 handler 链 |
| 前端对照 | axios 拦截器 / Koa 洋葱模型 —— 同一母题 |

## 四、项目踩过的坑（真实教训）

```text
[H2 Console 排查（10-26）](../Spring基础实战/SP8·Filter与Interceptor深入.md) [网页版](https://github.com/dreamChaser-lcc/ai-agent-explorer/blob/main/docs/Spring基础实战/SP8·Filter与Interceptor深入.md)：BodyCachingFilter 是链上的一环，它消费了请求体
→ 下游的 H2 Console（链尾）拿不到表单参数。
教训：责任链上每个节点改了行李，必须给下家"原样的行李"（包装器透传），
     这就是为什么 Wrapper 要正确实现 getParameter 系列。
```

## 五、面试速答

```text
Q：Filter 和 Interceptor 区别？
A：Filter 是 Servlet 规范（容器层，能拦静态资源）；Interceptor 是 Spring MVC
   的（DispatcherServlet 内，只拦 handler，能拿到 HandlerMethod）。
Q：责任链顺序谁定？
A：Filter 用 @Order/filterRegistration.order；Spring Security 用 addFilterBefore。
```

## 一句话

```text
责任链 = 请求过安检流水线，每层放行/拦截/改行李。
改行李必须透传（H2 Console 事故的教训）；@Order 定顺序。
```
