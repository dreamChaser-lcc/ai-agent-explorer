# 06 · 观察者与事件模式（Observer / Pub-Sub）

## 一、是什么：解耦"发生了"和"谁关心"

```text
同步调用（强耦合）：  任务完成 → 直接调用 剪辑服务.处理() → 直接调用 邮件服务.通知()
观察者（解耦）：      任务完成 → 只【发一个事件】
                                ├→ 谁订阅谁收到（剪辑服务）
                                └→ 谁订阅谁收到（邮件服务）
新增关心方：再注册一个订阅者即可，发布方零改动。
```

## 二、两种形态

```java
// ① 进程内事件（Spring 事件）
publisher.publishEvent(new TaskCompletedEvent(taskId));
@EventListener  // 订阅方
public void on(TaskCompletedEvent e) { ... }

// ② 跨进程消息（MQ / Kafka）
producer.publish("task-events", taskId);     // 项目 Kafka 版真身
consumer 消费（TaskExecutionConsumer）
```

| | 进程内事件 | MQ |
|---|---|---|
| 边界 | 同 JVM | 跨进程 |
| 可靠 | 进程挂就丢 | broker 持久化+重投 |
| 项目使用 | AuditAspect（Spring 事件做审计） | **场景⑥ 异步执行** |

| 例子 | 说明 |

## 四、面试速答

```text
Q：观察者 vs 发布订阅？
A：同思想两个词。严格区分：观察者是"点对点"（Subject 直持 Observer 列表）；
   Pub-Sub 引入中间 broker（Kafka），双方互不认识。
Q：事件什么时候用 MQ 什么时候用进程内？
A：同事务强一致 → 进程内；跨服务/要重试补偿/削峰 → MQ。
```

## 一句话

```text
观察者 = 发布方只管"喊一声"，订阅方各自反应。
进程内用 Spring Event；跨进程用 Kafka（项目场景⑥ 就是它的活体）。
```
