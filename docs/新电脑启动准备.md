# 新电脑启动准备

这份文档给未来在新电脑上启动这个项目时使用，重点是回答两件事：

1. 需要安装哪些环境
2. 第一次拉代码后需要做哪些配置

## 一、最低可运行环境

如果你的目标只是先把项目跑起来，看页面和接口联调效果，最低需要这些环境：

- Git
- Node.js + npm
- Java 21
- Maven 3.9.x

当前项目已经验证过的核心版本：

- Temurin OpenJDK 21
- Apache Maven 3.9.16
- 前端依赖：
  - Next.js 14.2.15
  - React 18.3.1
  - TypeScript 5.6.3

说明：

- 本地开发模式下，后端可以直接使用 H2 内存数据库
- 所以**最低可运行环境不强依赖 PostgreSQL**

## 二、建议安装环境

如果你希望体验更接近正式环境，建议再安装：

- PostgreSQL 16+
- Redis 7+

说明：

- PostgreSQL 用于默认后端配置和 Flyway 迁移
- Redis 当前主要是为后续扩展预留，当前 MVP 本地运行不是强依赖

## 三、推荐安装顺序

建议按这个顺序准备新电脑：

1. 安装 Git
2. 安装 Node.js LTS
3. 安装 Java 21
4. 安装 Maven 3.9.x
5. 克隆仓库
6. 安装前端依赖
7. 验证后端 Maven 构建
8. 用 `dev` 配置启动后端
9. 启动前端

## 四、需要安装什么

### 1. Git

用于拉取代码和提交版本。

验证命令：

```powershell
git --version
```

### 2. Node.js / npm

前端是 Next.js 项目，所以需要 Node.js。

验证命令：

```powershell
node -v
npm -v
```

建议：

- 优先安装当前稳定的 LTS 版本

### 3. Java 21

后端使用 Spring Boot 3.5，项目要求 Java 21。

#### 下载安装

推荐 [Adoptium Temurin OpenJDK 21](https://adoptium.net/download/)（免费、开源、LTS 长期支持）：

1. 打开下载页，选择 **Windows x64**，下载 `.msi` 安装包
2. 运行安装包，选择 **"Install for all users of this machine"（装给所有用户）**
3. 安装过程中**勾选 "将 Java 添加到 PATH"**（Add to PATH）
4. 建议安装路径保持默认（`C:\Program Files\Eclipse Adoptium\jdk-21.x.x.x-hotspot\`），也可以装到 D 盘

> **为什么不装 Java 25？** Java 25 也是 LTS，但本项目验证过的是 Java 21，使用验证过的版本最稳妥，避免兼容性问题。

#### 配置 JAVA_HOME 环境变量

即使安装时勾选了添加 PATH，也建议手动配 `JAVA_HOME`：

1. Win + R 输入 `sysdm.cpl` → **高级** → **环境变量**
2. 在**系统变量**中点击**新建**：

| 变量名 | 变量值（示例，替换为你的实际路径） |
|--------|--------------------------------------|
| `JAVA_HOME` | `C:\Program Files\Eclipse Adoptium\jdk-21.0.0.35-hotspot\` |

3. 在系统变量 **Path** 中，确认有 `%JAVA_HOME%\bin`（安装时勾选了添加 PATH 则一般已有，没有则手动加一条）

4. **新开一个终端**，验证：

```powershell
java -version
javac -version
```

> `javac` 是 Java 编译器（c = compiler），把 `.java` 源码编译成 `.class` 字节码。

### 4. Maven 3.9.x

后端构建和启动依赖 Maven。Maven 是 Java 项目的构建工具，类比前端的 `npm`，通过读取 `pom.xml`（类比 `package.json`）来管理依赖和构建。

> **注意别和 `nvm` 搞混**：`mvn`（Maven）管理 Java 项目，`nvm`（Node Version Manager）切换 Node.js 版本，名字像但完全不是一回事。

#### 下载安装

1. 打开 [Maven 下载页](https://maven.apache.org/download.cgi)，下载 **Binary zip archive**（例如 `apache-maven-3.9.16-bin.zip`）
2. 解压到你想要的目录，例如：
   - `C:\Program Files\apache-maven-3.9.16` 或
   - `D:\Tools\apache-maven-3.9.16`
3. 记住这个路径，下一步要用

#### 配置 MAVEN_HOME 和 PATH

1. Win + R 输入 `sysdm.cpl` → **高级** → **环境变量**
2. 在**系统变量**中点击**新建**：

| 变量名 | 变量值（示例） |
|--------|---------------|
| `MAVEN_HOME` | `C:\Program Files\apache-maven-3.9.16` |

3. 在系统变量 **Path** 中，**新建**一行：

```
%MAVEN_HOME%\bin
```

4. **新开一个终端**，验证：

```powershell
mvn -v
```

正常输出会显示 Maven 版本和它使用的 Java 路径。

> **装 C 盘还是 D 盘？** 都可以，只要 `MAVEN_HOME` 指对路径就行，不影响使用。

### 5. PostgreSQL（可选）

如果你想使用默认生产式配置，而不是 `dev` 本地 H2 配置，则需要安装 PostgreSQL。

默认配置对应：

- 地址：`localhost:5432`
- 数据库：`research_agent`
- 用户名：`postgres`
- 密码：`postgres`

对应文件：

- `backend/src/main/resources/application.yml`

### 6. Redis（可选）

当前默认配置里有 Redis 连接项：

- `localhost:6379`

对应文件：

- `backend/src/main/resources/application.yml`

不过当前 MVP 本地运行时，不把 Redis 作为必须启动项。

## 五、第一次拉代码后的步骤

### 1. 克隆仓库

```powershell
git clone https://github.com/dreamChaser-lcc/ai-agent-explorer.git
cd D:\Project\ai-agent-explorer
```

如果你实际放在别的目录，替换成你的真实路径即可。

### 2. 安装前端依赖

```powershell
cd D:\Project\ai-agent-explorer\frontend
npm install
```

### 3. 安装根目录依赖（可选）

根目录目前主要用于 OpenSpec 相关能力，如果你只想跑前后端，这一步不是强制。

```powershell
cd D:\Project\ai-agent-explorer
npm install
```

### 4. 验证后端构建

```powershell
cd D:\Project\ai-agent-explorer\backend
mvn test
```

这一步主要用于确认：

- Java 环境正常
- Maven 环境正常
- 后端依赖下载正常

## 六、启动前需要的配置

### 方案 A：本地开发快速启动

这是最推荐的方案，因为不需要先安装 PostgreSQL。

后端会使用：

- `application-dev.yml`
- H2 内存数据库

对应命令：

```powershell
cd D:\Project\ai-agent-explorer\backend
mvn spring-boot:run "-Dspring-boot.run.profiles=dev"
```

这个模式下：

- 自动使用 H2
- 自动执行 `schema-dev.sql`
- 自动打开 H2 控制台

访问地址：

- 后端健康检查：`http://localhost:8080/api/health`
- H2 控制台：`http://localhost:8080/h2-console`

### 方案 B：使用默认配置启动

如果你已经装好了 PostgreSQL，可以直接使用默认配置：

```powershell
cd D:\Project\ai-agent-explorer\backend
mvn spring-boot:run
```

但在此之前，你需要确保：

1. PostgreSQL 已启动
2. `research_agent` 数据库已经存在
3. 用户名密码与 `application.yml` 一致，或者通过环境变量覆盖

默认支持这些环境变量：

```powershell
$env:DB_URL="jdbc:postgresql://localhost:5432/research_agent"
$env:DB_USERNAME="postgres"
$env:DB_PASSWORD="postgres"
$env:REDIS_HOST="localhost"
$env:REDIS_PORT="6379"
$env:OPENAI_API_KEY="你的 key"
```

## 七、前端需要的配置

前端当前只需要一个最核心的环境变量：

- `NEXT_PUBLIC_API_BASE_URL`

参考文件：

- `frontend/.env.example`

内容如下：

```env
NEXT_PUBLIC_API_BASE_URL=http://localhost:8080
```

建议第一次拉代码后创建：

- `frontend/.env.local`

填入：

```env
NEXT_PUBLIC_API_BASE_URL=http://localhost:8080
```

然后启动前端：

```powershell
cd D:\Project\ai-agent-explorer\frontend
npm run dev
```

访问地址：

- 前端首页：`http://localhost:3000`

## 十一、常见问题

### 1. `mvn spring-boot:run` 报数据库连接失败

原因通常是：

- 你走的是默认配置
- 但本机没有 PostgreSQL

解决方式：

- 改用 `dev` 配置启动：

```powershell
mvn spring-boot:run "-Dspring-boot.run.profiles=dev"
```

### 2. `spring-boot:run` 提示找不到插件

原因通常是：

- 你不在 `backend` 目录里执行命令

应该在这里执行：

```powershell
cd D:\Project\ai-agent-explorer\backend
mvn spring-boot:run "-Dspring-boot.run.profiles=dev"
```

### 3. 前端请求不到后端

优先检查：

- 后端是否已经启动
- `frontend/.env.local` 是否配置了正确的 `NEXT_PUBLIC_API_BASE_URL`
