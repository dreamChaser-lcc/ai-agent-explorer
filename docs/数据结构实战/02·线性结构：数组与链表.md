## 一、数组：连续内存的"宿舍排房"

```text
内存： [ 7 ][ 14 ][ 21 ][ 28 ][ 35 ]
地址： 1000 1004  1008  1012  1016   ← 每间大小固定（int=4字节）

为什么能 O(1) 随机访问？
  arr[3] 的地址 = 1000 + 3 × 4 = 1012
  —— 一步乘加直达，不用数格子
```

**代价（一体两面）**：

```text
插入中间：后面全员搬家 → O(n)
  [7][14][28][35] 插 21 到位置 2：28/35 都要后移
删除中间：前面不动后面前移 → O(n)
扩容：申请更大的连续空间 + 全员复制 → O(n)（ArrayList 1.5 倍摊平成本）
```

**工程落点**：

| 落点 | 说明 |
|---|---|
| `ArrayList` | 默认容量 10 → 1.5 倍扩容（J3 §18.7 快问快答） |
| `String` | 内部 char 数组（不可变） |
| Kafka 日志段 | 顺序写 = 磁盘上最快的"数组追加"（Kafka 高吞吐的根基之一） |

## 二、链表：指针串联的"寻宝链"

```text
单链表：
  [7|next] → [14|next] → [28|next] → [35|null]
  每个节点 = 数据 + 指向下家的指针（散落在内存各处）

双链表（LinkedList 的真身）：
  null ← [prev|7|next] ⇄ [prev|14|next] ⇄ [prev|28|next] → null
```

**与数组完全互补**：

| 操作 | 数组 | 链表 |
|---|---|---|
| 随机访问 arr[i] | **O(1)** | O(n)（从头数） |
| 头部插入 | O(n) 搬家 | **O(1)**（改两个指针） |
| 已知节点前插入 | O(n) | **O(1)** |
| 内存 | 连续（缓存友好） | 分散（缓存不友好，每个节点单独分配） |

## 三、选型一句话（面试开口）

```text
"读多写少、要随机访问 → 数组（ArrayList）
 频繁头尾增删、或要当队列用 → 链表（ArrayDeque 其实更佳）
 按内容频繁中插 → 链表（但找到位置本身就要 O(n)——所以实际很少赢）"
```

---

## 一句话

```text
数组：连续换 O(1) 访问（代价：插删搬家）
链表：指针换 O(1) 插删（代价：访问要数、缓存不友好）
两者是互补的极端，工程首选几乎总是 ArrayList
```
