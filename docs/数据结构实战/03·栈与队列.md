## 一、两个"受限"的线性表

```text
栈（LIFO 后进先出）——只允许栈顶进出
  push → [  ][ ][ ][3][2][1] ← pop
  类比：羽毛球筒（只能从筒口拿）

队列（FIFO 先进先出）——尾部进、头部出
  offer → [ ][ ][1][2][3] → poll
  类比：食堂排队
```

**为什么"受限"反而是优点**：

```text
约束了操作面 → 语义清晰 → 并发控制简单
（能动的口子越少，要保护的规则越少——与 J8 "减少共享面"同思想）
```

---

## 二、工程落点（后端天天在用）

| 结构 | 落点 | 说明 |
|---|---|---|
| 栈 | **JVM 方法调用栈** | J9 §2 的"栈"就是它——每调用一个方法压一帧 |
| 栈 | 浏览器后退 / 撤销操作 | 每次 push 一条历史 |
| 栈 | 括号匹配校验 | 编译器/编辑器的基础活 |
| 队列 | **线程池的 workQueue** | J8 §3 七参数之一（任务排队的缓冲区） |
| 队列 | **Kafka 消息队列** | 生产者 offer 尾部、消费者 poll 头部 |
| 队列 | SSE 事件推送 | 事件按序送达 |
| 双端队列 | `ArrayDeque` | Java 官方推荐的栈+队列实现（性能优于老 Stack/LinkedList） |

---

## 三、Java 实现选型（一个小考点）

```text
要栈：  new ArrayDeque<>() 的 push/pop（别用老 Stack——继承 Vector 全表锁）
要队列：new ArrayDeque<>() 或 LinkedBlockingQueue（要阻塞/线程安全时）
要双端：ArrayDeque（数组实现，两端 O(1)）
```

---

## 一句话

```text
栈 = 只开一个口的线性表（LIFO）→ 方法调用、撤销
队列 = 开两个口的线性表（FIFO）→ 消息、任务排队
"受限"是设计出来的优点：口子少，规则少，并发好控制
```
