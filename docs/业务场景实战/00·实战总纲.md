## 二、每个场景的"课结构"（固定五步闭环）

```text
① 设计/审计 —— 盘现状（读代码）→ 列缺口假设（★ 用证据说话，不猜）
      ↓
② 编码 —— 改/补代码（小步、可验证）
      ↓
③ 运行验证 —— 真实启动 + 真实请求/日志，抓现场
      ↓
④ 固化 —— 把结论写成规范/文档（文档即产出）
      ↓
⑤ 落档提交 —— 讲义落档 + 总纲勾选 + git 提交（Conventional Commits + 中文）
```

**与 Java 基础实战的衔接**：场景中用到的语法/概念，**回查 J1–J9 讲义**；撞到没讲过的——**"遇卡即停"，随时增补 J10+**。

## 三、学习原则（继承既有约定）

1. **主轴 = 真实业务**：每个场景都是"设计 → 编码 → 部署/运行 → 验证 → 落档"的完整闭环；
2. **查证 > 记忆**：断言前先跑一遍（歪请求、真实日志、EXPLAIN……）——**用证据说话**；
3. **前端类比优先**：新概念先找 JS/TS 世界的锚点；
4. **部署面按需调用**：撞上基础设施需求时翻《学习路线规划》§三（G1–G9）；
5. **每课收尾固定动作**：验证通关 → 落档（文档 + 总纲勾选 + memory）→ **提交 git**（收官即提交，不跳步）；
6. ★ **数据层策略（场景③ 起）**：主线用 **MyBatis + 手写 SQL**，逐行讲 SQL 语法；JPA 仅作为既有基础设施提及——"**用封装永远学不会 SQL**"（用户决策）。
