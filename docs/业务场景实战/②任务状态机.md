## 1. 开课动机

任务有生命周期（`QUEUED → WAITING_FOR_CONFIRMATION → RUNNING → COMPLETED / FAILED / PAUSED / CANCELLED`）——**"状态 + 迁移规则"就是状态机**。核心问题：**谁都能按开关吗？**（"红绿灯"的意义：红灯时踩油门要被拦。）

## 2. 现状审计（2026-10-08，读码完成）

### 2.1 资产（底子）

| 资产 | 现状 |
|------|------|
| 状态表达 | `TaskStatus` 枚举（J6 成果——编译期防拼错） |
| 动作入口 | `ResearchTaskControlService`：confirmPlan / pause / resume / cancel（均 `@Transactional`） |
| 读事务规范 | 三个 QueryService 都用 `readOnly = true` ✓ |
| 枚举存储 | `@Enumerated(EnumType.STRING)`（存 "RUNNING" 而非 0/1） |

### 2.2 ★ 缺口 1：状态迁移**零校验**——"状态机没有机"

`pauseTask` 改造前全文核心：

```java
public void pauseTask(UUID taskId) {
    ResearchTaskEntity task = requireTask(taskId);
    task.setStatus(TaskStatus.PAUSED);   // ← 不看原状态，无脑覆盖！
    researchTaskRepository.save(task);
}
```

**推演**：`pause` 一个 **COMPLETED** 的任务 → 状态被硬改成 PAUSED——**篡改历史**：

| 动作 | 该有的前提 | 改造前表现 |
|------|-----------|-----------|
| pause | 非终态 | **任何状态都接受**（连 COMPLETED 都能"暂停"） |
| resume | PAUSED | 不看——非 PAUSED 也能"恢复"（还触发执行器！） |
| cancel | 非终态 | 不看——COMPLETED 也能"取消"→ 状态倒退 |

**后果**：数据被污染（已完成→已暂停）、日志与事实脱节、前端展示错乱。

### 2.3 ★ 缺口 2：无乐观锁（全项目 `@Version` **0 处**）

并发场景：两个浏览器同时"取消"+"暂停"——两条 UPDATE 都成功——**最后写的赢**（丢失更新）。

### 2.4 缺口 3（记录在案，本次未动手）：事务边界隐患

`confirmPlan` / `resume` **在事务内**调用 `researchTaskOrchestrator.startExecution(taskId)`——ASYNC 模式下线程池任务**可能先于事务提交**读到旧状态 → `shouldStop` 误判 → 任务静默退出。**（深水区，留待"事务边界"专题。）**

## 3. 三个概念（人话版）

### 3.1 幂等（Idempotent）——"按几次，结果都一样"

- **电梯类比**：按"3 楼"一次和十次，电梯都只去 3 楼；
- **定义**：同一操作执行 1 次与 N 次，对**系统状态的最终影响**相同（比的是状态，不是响应内容）；
- **判断口诀**：**"多做几次，有没有'多出来'的东西？"**；
- **HTTP 表**：GET（安全+幂等）/ PUT / DELETE 幂等；**POST 不幂等**（创建）——**幂等的最大价值 = 重试的安全性**。

### 3.2 事务（`@Transactional`）——"信封"

组内操作**要么全生效、要么全作废**；`readOnly=true` = 声明只读（规范：写不加、读必加）。

### 3.3 乐观锁（`@Version`）——"git 冲突检测"同款

每次 UPDATE 带 `WHERE id=? AND version=?`；被抢先改过 → 匹配 0 行 → 抛 `OptimisticLockingFailureException`。**对比悲观锁**：`SELECT ... FOR UPDATE` 一路锁着（稳但慢）。

### 3.4 思考题答案（课堂问答收录）

**题 1**——pause 已完成任务为什么不该报成功？
**答**：① 状态机意义——状态是"历史事实的摘要"，非法迁移=**篡改历史**（数据/日志/前端三方污染）；② 契约——200/204 = "我做到了"，对已完成任务无法实现"停下"的意图=撒谎。**正确规则**：目标状态已达成 → **幂等放行**；终态 → **拒绝（409/400）**；合法源状态 → 执行。**口诀：允许幂等、拒绝非法迁移。**

**题 2**——无锁并发双开会怎样？有 `@Version` 后后到者看到什么？
**答**：无锁 → 两条 UPDATE 都成功、**最后写的赢**（丢失更新；pause 方还收到 204）；事件日志两条都记 → 三方各说各话。有锁 → 后到者匹配 0 行 → 抛异常 → **值班室转 409**（"请刷新后重试"——明确失败 > 静默错误）。**口诀：无锁最后写的赢；有锁先写的赢、后到的被拒。**

## 5. 验证记录（2026-10-08，7 步实测全中）

| 步 | 操作（对 WAITING 状态的实验任务） | 实测 | 判定 |
|----|--------------------------------|------|------|
| ① | resume（非 PAUSED） | **400** `"任务当前状态为 WAITING_FOR_CONFIRMATION，无法恢复执行"` | 严格守卫 ✓ |
| ② | pause（首次） | **204** | 合法迁移 ✓ |
| ③ | pause（再次） | **204** | **幂等** ✓ |
| ④ | cancel | **204** | 合法迁移 ✓ |
| ⑤ | pause（已 CANCELLED） | **400** `"任务已结束（CANCELLED），无法暂停"` | ★ **终态拒绝**（改造前会篡改） |
| ⑥ | GET 详情 | `"status":"CANCELLED"` | ★ **未篡改** |
| ⑦ | cancel（再次） | **204** | **取消幂等** ✓ |

**★ 物证细节**：第 ⑤ 步实测发出于 21:05:08，而 ⑥ 查到的 `updatedAt = 21:04:56`（= 第 ④ 步 cancel 时刻）——**⑤ 没有产生任何 UPDATE**——"被拦在写库之前"的数据库级铁证（`updatedAt` 是最朴素的审计线索）。

**工具链插曲（两集）**：

1. PS 传 JSON 引号坑：`-d '{"title":"..."}'` 在 PowerShell 里双引号被剥离 → 后端收到非法 JSON → **400 `MALFORMED_REQUEST`**（★ 场景① 固化的错误码一眼定位）；解法：`Invoke-RestMethod`（原生 JSON）或 `\"` 转义；
2. 引号未闭合 → PS 进入 `>>` 续行等待 → Ctrl+C 逃脱；**URL 无空格时不必加引号**。

## 6. ★ 固化：状态机规则表（本场景产出）

| 动作 | 任务当前状态 | 结果 |
|------|-------------|------|
| `pause` | 终态（COMPLETED/FAILED/CANCELLED） | **400** `"任务已结束（X），无法暂停"` |
| `pause` | 已 PAUSED | **204**（幂等） |
| `pause` | 其他（WAITING/RUNNING…） | **204** → PAUSED |
| `resume` | PAUSED | **204** → RUNNING |
| `resume` | 非 PAUSED | **400** `"任务当前状态为 X，无法恢复执行"` |
| `cancel` | 已 CANCELLED | **204**（幂等） |
| `cancel` | COMPLETED / FAILED | **400** |
| `cancel` | 其他 | **204** → CANCELLED |
| `confirmPlan` | 非 WAITING_FOR_CONFIRMATION | **400** |
| 任意并发写冲突 | — | **409** `CONCURRENT_CONFLICT`（乐观锁兜底） |

| code | HTTP | 触发场景 |
|------|------|---------|
| `CONCURRENT_CONFLICT` | 409 | 乐观锁冲突（并发修改，请刷新后重试） |

## 7. 复盘与关联地图

**复盘收获**：

1. **"状态机"不是枚举，是"守卫"**——枚举只是标签；规则（谁能迁到谁）必须有人执行——本场景把它收在了**服务层守卫**（`requireStatus` / `requireNotTerminal` / `isTerminal`）；
2. **幂等的边界**：SET 语义（pause/cancel）天然可做成幂等——但 **resume 不能宽松**（会重复触发执行器）——"幂等 = 看副作用，不是看状态码"；
3. **乐观锁是第二道防线**：状态守卫挡"逻辑非法"，`@Version` 挡"物理竞态"——纵深防御；
4. **时间戳会作证**：`updatedAt` 停在何处，就是"最后一次真实写入"的位置。

**关联课程**：

| 课 | 关联点 |
|----|--------|
| J6 | `isTerminal()` = 枚举带方法；终态/中间态概念；PAUSED 的"能回来" |
| J8 | 并发与线程池（缺口 3 的竞态窗口正是 J8 的"事务边界"深水区） |
| 场景① | 错误码/handler 模式复用（INVALID_STATE 已有、409 新增）；`MALFORMED_REQUEST` 破案 |
| 场景④（预告） | 幂等的另一半：POST 创建如何做幂等（幂等键/唯一索引） |
