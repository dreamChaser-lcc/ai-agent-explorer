# 后端架构与执行流程

> 基于 2026-08-10 代码分析整理，便于后续理解和回顾。

---

## 一、分层架构（类 DDD）

```
请求 → api/（Controller）→ application/service/（编排层）→ infrastructure/
                                    ↑                         ├── persistence/（数据库）
                                    │                         └── tools/（外部工具）
                               shared/（枚举 + 异常，各层共用）
```

### 各层职责速查

| 包路径 | 职责 | 关键注解 |
|--------|------|----------|
| `api/controller/` | 接收 HTTP 请求、参数校验、返回响应，**不写业务逻辑** | `@RestController` |
| `api/request/` | 前端请求体 DTO（record 类型） | — |
| `api/response/` | 返回给前端的响应体 DTO（record 类型） | — |
| `application/service/` | **全部业务逻辑**：编排流程、调用工具、操作数据库 | `@Service` |
| `domain/model/` | 预留领域模型层（当前 MVP 中空） | — |
| `infrastructure/config/` | 技术配置（跨域、线程池等） | `@Configuration` |
| `infrastructure/persistence/entity/` | JPA 数据库表映射 | `@Entity` |
| `infrastructure/persistence/repository/` | 数据库操作接口（JpaRepository） | — |
| `infrastructure/tools/` | 实现 ResearchTool 接口的工具 | `@Component` |
| `shared/enums/` | 枚举定义（TaskStatus、StepType 等） | — |
| `shared/exception/` | 自定义异常 | — |

## 三、完整数据流

### 3.1 创建任务

```
前端 POST /api/tasks { title, goal, executionMode }
  ↓
ResearchTaskController.createTask()
  ↓
ResearchTaskCommandService.createTask()
  ├─ new ResearchTaskEntity → set 各项 → save()
  └─ researchPlanningService.generateInitialPlan()
       ├─ 创建 ResearchPlanEntity
       ├─ 生成 5 个 ResearchStepEntity
       │    步骤1: SEARCH（READY）
       │    步骤2: FETCH（PENDING）
       │    步骤3: SUMMARIZE（PENDING）
       │    步骤4: CITATION_EXTRACT（PENDING）
       │    步骤5: REPORT（PENDING）
       ├─ 创建 HumanConfirmationEntity（PENDING）
       ├─ 更新任务状态 → WAITING_FOR_CONFIRMATION
       └─ SSE 推送 "plan-generated"
```

### 3.2 确认计划

```
前端 POST /api/tasks/{id}/confirm { approved: true }
  ↓
ResearchTaskController.confirmPlan()
  ↓
ResearchTaskControlService.confirmPlan()
  ├─ 更新确认记录 → APPROVED
  └─ orchestrator.startExecution()
       ├─ ASYNC 模式 → 提交线程池 → Controller 立即返回
       └─ SYNC 模式  → 直接执行 → 跑完才返回
```

### 3.3 执行步骤（Orchestrator.executeTask）

```
对每个步骤（Step 1→5）循环：
  ├─ shouldStop() 检查（暂停/取消/失败/已完成/等待确认）
  ├─ updateTaskForStep() → 任务状态 RUNNING + SSE推送
  ├─ createRunningExecution() → 步骤执行记录
  │
  ├─ 分支判断：
  │   ├─ Step 5 REPORT:
  │   │   └─ reportAssemblyService.buildReport() → 汇总前序结果
  │   └─ Step 1-4 普通步骤:
  │       └─ toolRegistry.execute(stepType, context)
  │           ├─ SEARCH → WebSearchResearchTool → 模拟 3 条来源
  │           ├─ FETCH  → WebFetchResearchTool → 抓取正文
  │           ├─ SUMMARIZE → SummarizeResearchTool → 生成总结
  │           └─ CITATION → CitationResearchTool → 提取引用
  │
  ├─ persistSourceDocuments() → 工具返回的来源持久化
  ├─ completeExecution() → 执行记录 SUCCESS + 耗时
  ├─ promoteNextStep(N → N+1) → PENDING → READY
  └─ SSE 推送 "step-completed"
  │
  （如果某步失败 → failExecution() → 任务 FAILED → 停止）
  │
全部完成后 → markTaskCompleted() → COMPLETED + SSE推送
```

### 3.4 SSE 实时推送

```
前端: new EventSource("/api/tasks/{id}/stream")
  ↓
TaskProgressStreamService.subscribe()
  ├─ 创建 SseEmitter（永不超时）
  ├─ 存入 emittersByTaskId Map
  ├─ 注册 onCompletion/onTimeout/onError 回调
  └─ 发送 "connected" 确认事件

编排器中各处调用 publish():
  ├─ "plan-generated"   → 计划生成完毕
  ├─ "step-running"     → 某步骤开始执行
  ├─ "step-completed"   → 某步骤执行完成
  └─ "task-status"      → 任务状态变化（COMPLETED/FAILED）
```

## 四、步骤状态流转

```
PENDING → READY → RUNNING → COMPLETED
              ↑                ↓
         promoteNextStep    FAILED（任务终止）
```

- 第 1 步初始：READY
- 第 2-5 步初始：PENDING
- 前一步完成时：`promoteNextStep` 把 PENDING → READY

## 五、工具注册表（策略模式）

```
ResearchTool 接口
  ├─ getSupportedStepType() → 声明负责的步骤类型
  └─ execute(context) → 执行工具逻辑

ResearchToolRegistry（构造器）
  ├─ Spring 自动注入所有 ResearchTool 实现
  └─ 构建 EnumMap<StepType, ResearchTool> 映射表

新增工具只需：
  1. 实现 ResearchTool 接口
  2. 加 @Component 注解
  3. 注册表自动纳入（编排层无需修改）
```

## 六、关键设计点

### 6.1 异步 vs 同步

| 模式 | 行为 | 适用场景 |
|------|------|----------|
| SYNC | 阻塞执行，所有步骤跑完才返回 | 测试、简单场景 |
| ASYNC | 线程池异步执行，主线程立即返回 | 耗时任务，前端通过 SSE 订阅进度 |

### 6.2 任务停止条件

以下任一状态出现时 `shouldStop()` 返回 true：
- PAUSED（已暂停）
- CANCELLED（已取消）
- FAILED（已失败）
- COMPLETED（已完成）
- WAITING_FOR_CONFIRMATION（等待确认）

### 6.3 MVP 当前状态

- 搜索工具：`WebSearchResearchTool` 返回 hardcoded 模拟数据
- 计划生成：`ResearchPlanningService` 使用 5 步模板，非 LLM 动态规划
- 用户系统：`createdBy` 硬编码为 `"demo-user"`
- 后续可逐一替换为真实实现，架构无需大改

## 七、路由表

```
POST   /api/tasks                  → 创建任务
GET    /api/tasks                  → 获取任务列表
GET    /api/tasks/{taskId}         → 获取任务详情
GET    /api/tasks/{taskId}/executions → 获取步骤执行时间线
GET    /api/tasks/{taskId}/events    → 获取任务事件日志
GET    /api/tasks/{taskId}/stream    → 订阅 SSE 进度推送
POST   /api/tasks/{taskId}/confirm   → 确认/拒绝研究计划
POST   /api/tasks/{taskId}/pause     → 暂停任务
POST   /api/tasks/{taskId}/resume    → 恢复任务
POST   /api/tasks/{taskId}/cancel    → 取消任务
```
