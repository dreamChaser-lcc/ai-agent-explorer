# 专题 · 静态语言 vs 动态语言——两套世界观（JS 与 Java 对照）

> **定位**：这不是新知识课——是把散落在 **J1–J9** 里的困惑，归到**一根主线**上。
> **用法**：以后遇到"为什么 Java 非要这样"的问题，先回这篇——**先问一句："这事发生在编译期还是运行期？"**——一半的问题会自己散开。
> **建立**：2026-10-07（源自 J8 课堂追问"Java 为什么不能像 JS 一样直接传方法名"）

---

## 0. 一句话定义

| | 动态语言（JS / Python / Ruby） | 静态语言（Java / C# / Go / Kotlin） |
|---|---|---|
| **类型何时确定** | **运行时**——变量装什么都行（`let x = 1; x = "a"`） | **编译时**——声明什么装什么（`String x = ...`） |
| **错误何时暴露** | **运行时炸**（红屏：`undefined is not a function`） | **编译时拦**（写代码时红波浪线，很多错误根本发不出去） |

**TS 的特殊位置**（你的家底）：**TS = 动态语言的肉身 + 静态语言的盔甲**——类型只在"检查期"存在，编译后擦掉、变回 JS。**所以 TS 写得好的人，已经懂静态语言的一半。**

---

## 1. ★ 总钥匙：一张"时间轴"

两种语言的**根本分岔**就在这里：

```text
静态语言（Java）：   写代码 ──→ 【编译】 ──→ 运行
                              ★ 编译器站岗：
                              - 类型对不对（J1）
                              - 接口方法全实现了吗（J2）
                              - 泛型标签合规吗（J3）——查完就"擦掉"
                              - 受检异常处理了吗（J4）
                              - switch 穷尽了吗（J6）
                              - 方法真的能覆盖吗（J7 @Override）

动态语言（JS）：     写代码 ──→ 运行
                              ★ 运行时才暴露：
                              - undefined is not a function
                              - Cannot read property 'x' of undefined
```

> **静态语言 = 把大量"检查"从运行时提前到编译期。**
> 代价：写起来啰嗦（要声明类型）；收益：**错误在出错之前就被抓住**。

**★ 万能发问**（把这句话刻进脑子）：

> 遇到任何 Java 困惑，先问：**"这事是编译期的事，还是运行期的事？"**

用它回看你学过的每一课——**J2 的"编译看左边、运行看右边"就是这个问句的最经典应用**。

## 2. 总对照表

| 维度 | 动态语言（JS） | 静态语言（Java） |
|------|--------------|----------------|
| 类型确定时机 | 运行时 | **编译时** |
| 变量能装什么 | 任意（类型随值变） | 声明什么装什么 |
| 错误暴露时机 | 运行时 | 编译期（大量）+ 运行期（其余） |
| 执行步骤 | 一步：跑 | 两步：**先编译**（检查+翻译），再跑 |
| 部署产物 | 源码（直接跑/打包） | **.class 字节码** → JVM 执行 |
| 方法/函数是"值"吗 | ✅ 函数是一等公民，随便传 | ❌ 方法不是值——**要包装**（J8 的 lambda / `::`） |
| 自省（看自己） | 天生就会（`Object.keys`、`obj[name]()`） | 要**开后门**——反射（J7） |
| 类型检查谁做 | 运行时（`typeof`） | 编译器（提前做完；**泛型查完还擦除**——J3） |
| "契约"（接口） | 可选（TS 才有，且擦除） | **核心工具**（J2：编译器按契约检查、多态按契约调用） |
| 给"检查阶段"传话的方式 | 无（没有独立检查阶段） | **注解**（J7：`@Override` 给编译器、`@Service` 给框架） |
| 安全网成本 | 低（随便写） | 高（要声明、要处理异常） |

## 3. ★ 归位表：你问过的每个问题，全在这里对号

这是本篇最重要的表——**你一路上困惑过的具体问题，根都在"静态 vs 动态"**：

| 你曾经的困惑（哪一课的） | 从"静态/动态"看 |
|------------------------|----------------|
| 为什么变量都要写类型？`List<TaskSummaryResponse>`（J3） | 静态语言的入场券——**编译器要拿它做检查** |
| 泛型 `<T>` 为什么"运行时消失了"？（J3 擦除） | 泛型是**编译期**的工具——查完就退休，运行时不需要 |
| "编译看左边、运行看右边"？（J2） | 静态语言的**双身份**：编译期看声明类型、运行期看真身——**两个世界并行存在** |
| `@Override` 为什么不用活到运行时？（J7） | 它服务**编译器**（编译期的事）——干完即扔（SOURCE 档） |
| 为什么不能像 JS 一样直接传方法名？（J8） | 方法不是值（静态设定）——`() ->` / `::` 是"包装后传递"的通道 |
| `Runnable`/函数式接口为什么存在？（J8） | 静态语言**模拟"传函数"**的官方姿势（借接口当"函数护照"） |
| 为什么到处是接口？（J2） | 静态世界里，"契约"让**编译器的检查**更有用，也让模块解耦 |
| 为什么 Java 有反射？（J2/J7） | 静态语言**开的后门**——平时锁死（编译期确定），想让运行时"像 JS 一样自由"就得翻说明书 |
| 为什么 Java 有那么多注解？（J7） | 静态语言给"**检查时代**（编译期/框架启动期）"传话的通道 |
| 为什么 JS 的 `?.` 在 Java 里没有，只有 Optional？（J3） | 语言演进路径不同——Java 用"库 + 检查"补动态语言语法糖的课 |
| 为什么 Spring 能有"魔法"？（J2） | **框架 = 用后门（反射/代理）把静态语言玩出动态效果**的产物 |

## 4. 双世界并行：同一份代码，活在两个时代

Java 代码**同时活在两个世界里**——每段代码都能问"它属于哪个时代"：

```java
List<TaskSummaryResponse> listTasks() { ... }
//   ↑ 编译期的"标签"——运行时不认（擦除）——【编译世界】

@Transactional
public void executeTask(UUID taskId) { ... }
// ↑ 注解给读者看：编译期没人读它，Spring【运行世界】读它才造代理

researchTaskExecutor.execute(() -> executeTask(taskId));
//                                   ↑ lambda 在【编译期】被翻译成匿名对象——【运行世界】执行
```

**练习**（把"万能发问"用起来）——

| 现象 | 发生在哪个世界？ |
|------|----------------|
| 泛型的 `<T>` | 编译期（查完擦除） |
| CGLIB 代理类 `$$SpringCGLIB$$0` | 运行期（启动时生成） |
| `@Override` 的检查 | 编译期 |
| 反射 `invoke` | 运行期 |
| 受检异常"不处理不给编译" | 编译期 |
| 线程池里任务的执行 | 运行期 |
| `@ConfigurationProperties` 绑定 yml | 运行期（启动时） |
| "接口必须全实现，否则编译错" | 编译期 |

## 5. 前端↔后端 对照字典（速查）

| 概念 | JS / TS | Java |
|------|---------|------|
| 变量声明 | `let/const`（无类型） | `String name`（类型+名字） |
| 类型检查 | 无（或 TS 检查期） | 编译器（编译期） |
| 类型擦除 | TS 类型编译后擦掉 | Java 泛型编译后擦掉（**同款**） |
| 传函数 | `fn` / `() => fn(x)` | `this::fn` / `() -> fn(x)`（J8） |
| 空安全 | `?.` / `??`（ES2020 才有） | `Optional` / 判空（语言没给语法——J3） |
| "装饰器" | TS 装饰器 | **注解**（`@Retention` 决定寿命——J7） |
| 自省/动态调用 | `obj[key]()`（天生） | 反射（`getMethod`→`invoke`——J7） |
| 类/对象的"档案" | `constructor` / `prototype` | `Class` 对象（`Xxx.class`） |
| 编译产物 | 无（或打包/转译） | `.class` 字节码（JVM 执行） |
| 报错主要时机 | 运行时 | **编译期**（大头） |

## 6. 各自的代价与收益（没有好坏，只有取舍）

**静态语言（Java）**：

| 收益 | 代价 |
|------|------|
| 错误提前抓（编译期拦掉一类问题） | 写起来啰嗦（类型声明、异常声明） |
| IDE 提示/补全强的飞起（编译器知道类型） | 灵活度低（要绕路：反射/包装） |
| 重构安全（改名全局跟随） | 改类型影响面大（全链路表态） |
| 大团队协作好（类型即文档） | 学习曲线陡（概念多：接口/泛型/注解…） |
| 运行性能（类型定死→JIT 好优化） | —— |

**动态语言（JS）**：

| 收益 | 代价 |
|------|------|
| 灵活、写得快、心智轻 | 错误可能跑到线上才炸（`undefined` 虐我千百遍） |
| 鸭子类型/原型链自由 | 大项目难维护（没有"契约"约束） |
| 无需编译、即改即跑 | IDE 提示弱（除非上 TS） |

**趋势一句话**：**动态语言在"加类型"（TS / Python typing），静态语言在"减冗长"（`var`/类型推断）——两个世界在往中间靠。**

## 7. 为什么 Java"敢锁死"还留后门——设计哲学

```text
锁（静态）  →  让编译器能帮你干活：检查、优化、提示、重构
后门们      →  保留"动态"的能力：反射 / 字节码 / 注解处理器
        ↓
★ 框架的本质 = 用后门把静态语言"玩"出动态效果：
   Spring 的扫描、注入、代理、条件装配……全是反射（J2/J7 你已逐个学过）
```

> **Java = 静态语言的规矩 + 一批精心设计的后门——框架们住在后门里，替你把"动态"的活干了。**

---

## 8. 收拢：一句话总纲

> **动态语言把决定留到运行时**（灵活，风险后置）；
> **静态语言把决定提前到编译时**（约束，风险前置）。
>
> **Java 的一切特色**——类型、接口、泛型、注解、反射的"存在感"——**都是这一个选择的漫长下游**。

**下次遇到"为什么 Java 要这样"——先问：编译期，还是运行期？** 🎯
