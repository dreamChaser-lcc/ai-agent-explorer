## 0. 教材原文（先通读一遍）

### 0.1 ApiError.java

```java
public record ApiError(
        String code,
        String message,
        String path,
        OffsetDateTime timestamp,
        List<FieldViolation> fields) {

    public record FieldViolation(String field, String reason) {
    }

    public static ApiError of(String code, String message, String path) {
        return new ApiError(code, message, path, OffsetDateTime.now(), List.of());
    }

    public static ApiError of(String code, String message, String path, List<FieldViolation> fields) {
        return new ApiError(code, message, path, OffsetDateTime.now(), fields);
    }
}
```

### 0.2 ApiExceptionHandler.java（节选核心片段）

```java
@RestControllerAdvice
public class ApiExceptionHandler {

    private static final Logger log = LoggerFactory.getLogger(ApiExceptionHandler.class);

    @ExceptionHandler(MethodArgumentNotValidException.class)
    @ResponseStatus(HttpStatus.BAD_REQUEST)
    public ApiError handleValidationError(MethodArgumentNotValidException exception, HttpServletRequest request) {
        List<ApiError.FieldViolation> fields = exception.getBindingResult().getFieldErrors().stream()
                .map(fieldError -> new ApiError.FieldViolation(fieldError.getField(), fieldError.getDefaultMessage()))
                .toList();
        return ApiError.of("VALIDATION_ERROR", "请求参数校验失败", request.getRequestURI(), fields);
    }

    @ExceptionHandler(Exception.class)
    @ResponseStatus(HttpStatus.INTERNAL_SERVER_ERROR)
    public ApiError handleUnexpected(Exception exception, HttpServletRequest request) {
        log.error("未处理异常: {} {}", request.getMethod(), request.getRequestURI(), exception);
        return ApiError.of("INTERNAL_ERROR", "服务器内部错误", request.getRequestURI());
    }
}
```

## 1. package：文件第一行为什么这么长

```java
package com.aiexplorer.researchagent.api.response;
```

- **一句话**：声明"我这个文件属于哪个包（package）"——**包 = 类的"文件夹"**。
- 命名规则：**域名倒写** + 项目名 + 模块路径（`com.aiexplorer` ← aiexplorer.com 倒过来）。
- 前端类比：**import 路径**——`import { x } from "@/api/response"`，一个道理。
- **项目约定**：`api`（接口层）/ `application`（应用层）/ `domain` / `infrastructure`（基础设施）/ `shared`——**包的层级 = 架构的层级**。

## 2. import：把"别人家的类"引进来

```java
import java.time.OffsetDateTime;
import java.util.List;
import com.aiexplorer.researchagent.api.response.ApiError;
```

- **一句话**：用别的包里的类，先声明"我要用它"；否则代码里就得写全名（`java.time.OffsetDateTime.now()`）。
- 三种形态：
  | 形态 | 例子 | 说明 |
  |------|------|------|
  | 单类导入 | `import java.util.List;` | 最常见 |
  | 通配导入 | `import java.util.*;` | 省事但**不推荐**（看不清用了谁） |
  | 静态导入 | `import static java.util.Objects.requireNonNull;` | 导入"静态方法"直接裸调用（**项目里少用**） |
- 前端类比：ES Module 的 `import` —— 一模一样的心智。

## 3. 注解（@）：贴在代码上的"标签"——语法层

```java
@RestControllerAdvice          // 贴在类上
public class ApiExceptionHandler {

    @ExceptionHandler(...)     // 贴在方法上
    @ResponseStatus(...)       // 可以贴多个
    public ApiError handleValidationError(...) { ... }
```

- **一句话**：注解 = **以 `@` 开头的"标签"**，可以贴在类/方法/字段/参数上；**它本身不干活**，等"读标签的人"（框架）来消费（第 6 课讲过的"声明-注册-调用"）。
- 语法形态：
  - 无参数：`@Override`
  - 带参数：`@ResponseStatus(HttpStatus.BAD_REQUEST)` —— 括号里像"调方法"（其实是**给属性赋值**）
- 前端类比：**TS 装饰器**（`@Component()`）——几乎一样。
- **J7 会专门深挖**注解体系（元注解、自定义注解、怎么自己写一个）。

## 4. record：不可变数据类（≈ TS interface + 自动生成实现）

```java
public record ApiError(
        String code,
        String message,
        String path,
        OffsetDateTime timestamp,
        List<FieldViolation> fields) { ... }
```

- **一句话**：`record` 是 Java 给"**纯粹装数据**的类"准备的语法糖——**参数列表即字段**。
- 编译器**自动生成**：
  | 自动生成 | 效果 |
  |---------|------|
  | 全参构造器 | `new ApiError("A", "B", "C", now, list)` 直接可用 |
  | 访问器方法 | **名字就是字段名**：`apiError.code()`（**注意不是 `getCode()`**！） |
  | `equals` / `hashCode` / `toString` | 值语义比较、打印（调试友好） |
- **不可变**：字段默认 `final`、没有 setter——**创建后不能改**。
  前端类比：`Readonly<{ code: string; ... }>`——**对**（≈ TS interface + `Readonly` + 自动构造器）。
- 使用时机：**DTO 首选**（请求体 / 响应体）——项目里 `api/request`、`api/response` 下**全是 record**。
- 什么时候**不用** record：需要可变字段 / 需要继承 / 是"有行为的主角类"（如 Service）→ 用普通 `class`。

## 5. 嵌套类型：record 里再声明 record

```java
public record ApiError(...) {
    public record FieldViolation(String field, String reason) { }
}
```

- **一句话**：类型也可以"住在"另一个类型里，用 `外类.内类` 引用（`ApiError.FieldViolation`）。
- **为什么嵌套**：`FieldViolation` 只服务于 `ApiError`——**放一起 = 内聚**、不污染外层命名空间。
- 前端类比：TS 里 `interface ApiError { fields: FieldViolation[] }`——**接口定义常写一起**，同样的组织思路。

## 6. static：属于"类"，不属于"对象"

```java
public static ApiError of(String code, ...) { ... }
private static final Logger log = ...;
```

- **一句话**：`static` 成员属于**类本身**，**不用 `new` 就能用**。
  ```java
  ApiError.of(...)      // ✅ 直接"类名.方法"
  // 而不是先 new 一个 ApiError 再调 of
  ```
- 判断标准（好记版）：**方法体里没用到 `this`（实例字段）→ 可以考虑 static**。
- 前端类比：`Array.isArray()`（挂在类上的工具方法）vs `[].push()`（实例方法）——**一个是"类的"，一个是"对象的"**。
- 项目里的 `of(...)` 是经典用途：**工厂方法**（把"怎么造对象"的细节收进类自己家里，调用方 `ApiError.of(...)` 一句话）。

## 7. final：不可变的三种含义

| 位置 | 含义 | 项目例子 |
|------|------|---------|
| 变量 | **只能赋值一次**（≈ JS `const`） | `private static final Logger log` |
| 方法 | 不能被子类**覆写** | （项目暂未用） |
| 类 | 不能被**继承** | **record 隐含 final**——`ApiError` 不可被继承 |

**`private static final Logger log` 逐词读**：

```
private  → 只在本类内用（外面不许碰）
static   → 类级共享（一个类就一个 logger，不需要每个 ApiError 实例各带一个）
final    → 初始化后不再变（logger 的引用永不重赋）
```

> 常量命名惯例：全大写下划线（`MAX_SIZE`）；但 logger 惯例就叫 `log`（小写，社区约定）。

## 8. 访问控制：public / private 在保护什么

```java
public record ApiError(...)         // 类对外可见
public record FieldViolation(...)   // 嵌套类也 public（外面要构造它）
public static ApiError of(...)      // 方法 public（给外界用）
private static final Logger log     // 字段 private（内部实现细节）
```

- **一句话**：**能少公开就少公开**——`public` 是"承诺"（别人依赖了就不能随便改），`private` 是"自由"（想怎么改怎么改）。
- 前端粗糙对照：JS 没有编译期访问控制（`#private` 字段算轻量版）——Java 是**编译器强制**的。
- **高级工程师的口味**：**对外最小 API 面**——`ApiError` 里"暴露什么"都是设计决策。

## 9. 方法：签名、返回值、参数

```java
public ApiError handleValidationError(MethodArgumentNotValidException exception, HttpServletRequest request) {
    ...
    return ApiError.of(...);
}
```

- **方法签名** = 名字 + 参数列表：`handleValidationError(MethodArgumentNotValidException, HttpServletRequest)`
- 逐段读：
  | 片段 | 含义 |
  |------|------|
  | `public` | 访问级别 |
  | `ApiError` | **返回类型**（return 的东西必须能赋给它） |
  | `handleValidationError` | 方法名（动词短语，见名知意） |
  | `(…, …)` | 参数列表：类型 + 参数名 |
  | `return …;` | 返回（无返回值则写 `void`） |
- **一个常被忽略的真相**：**Java 的参数传递一律是"值传递"**——传对象时传的是"**引用的拷贝**"（像复印件门牌号）——所以方法里改**对象内部**会影响外面，但"让参数指向别的对象"不会。**J3/J2 会用实验演示**。

## 10. lambda：`fieldError -> new ...`（≈ 箭头函数）

```java
.map(fieldError -> new ApiError.FieldViolation(fieldError.getField(), fieldError.getDefaultMessage()))
```

- **逐字对照你的老本行**：

```javascript
// 前端（箭头函数）
list.map(fieldError => new FieldViolation(fieldError.getField(), fieldError.getDefaultMessage()))

// Java（lambda）
list.stream().map(fieldError -> new ApiError.FieldViolation(fieldError.getField(), fieldError.getDefaultMessage()))
```

- **语法构成**：`参数 -> 表达式`（表达式体）；需要多条语句时写 `参数 -> { 语句; return 值; }`。
- 说人话：**lambda = 一段"没名字的函数"**，传给别的函数去用。
- 一个补充概念（点到为止）：Java 的 lambda 必须赋给**"只有一个抽象方法的接口"**（函数式接口）——`map` 的参数类型 `Function<T, R>` 就是。**J5 深讲**。

## 11. 点链调用：为什么能一直点下去

```java
exception.getBindingResult()   // → BindingResult
        .getFieldErrors()      // → List<FieldError>
        .stream()              // → Stream<FieldError>
        .map(fieldError -> …)  // → Stream<FieldViolation>
        .toList();             // → List<FieldViolation>
```

- **一句话**：**每一个方法的返回值又是对象**，所以可以继续点——**链式 API**。
- 前端类比：`arr.filter(...).map(...).join("")`——**同款链子**。
- **读链技巧**：**从里往外读**——先看第一个返回什么，把"类型流转"写在旁边（上面注释就是）——**类型会替你把路标出来**。

## 12. 日志惯例：`private static final Logger log` 的典故

```java
log.error("未处理异常: {} {}", request.getMethod(), request.getRequestURI(), exception);
```

- 每个类head一个**类级 logger**、名字叫 `log`——**社区统一惯例**（方便排查时按类名过滤）。
- `{}` 是**占位符**：**不要用字符串拼接**（`"a" + b`）——占位符只在"真要打印时"才拼装（性能 + 安全）。
- `log.error(...)` 最后一个参数传 `exception` → **打印完整堆栈**（"异常给日志看、响应给用户看"——第 6 课的原则，语法上就是这么实现的）。
- 前端类比：`console.error(...)` 的"后端正式版"（分级：`debug/info/warn/error`）。

## 13. Javadoc 注释规范

```java
/**
 * 统一的错误响应契约（全局异常处理使用）。
 * ...
 */
public record ApiError(...)
```

- `/** ... */` = **Javadoc**（文档注释）：贴在下一位成员上方，IDE 悬停会显示、可生成 HTML 文档。
- 与普通注释的区别：`//` 给人看；`/** */` 给"使用者"看（**面向调用方写**）。
- 项目风格：**中文 Javadoc + 关键决策写进注释**（如"设计约定：成功=裸资源"）——**好注释解释 Why，而非 What**。

## 15. 项目关联地图（本课语法在仓库里的分布）

| 语法 | 仓库里的"高发区" |
