# J6 · 枚举（精读讲义）

> **教材**：`shared/enums` 包 14 个枚举（`TaskStatus` / `StepStatus` / `ExecutionMode` …）
> **一句话主题**：**状态为什么都用枚举**——类型安全、自文档、switch 穷尽（"编译器站岗"）。
> **建立**：2026-10-07（含 EnumLab 实测：穷尽检查报错现场）

---

## 0. 教材三样本

```java
public enum TaskStatus { DRAFT, QUEUED, PLANNING, WAITING_FOR_CONFIRMATION,
                         RUNNING, PAUSED, COMPLETED, FAILED, CANCELLED }   // 任务的一生（9 个）
public enum StepStatus { PENDING, READY, WAITING_CONFIRMATION,
                         COMPLETED, FAILED, SKIPPED }                       // 步骤状态机（6 个）
public enum ExecutionMode { SYNC, ASYNC }                                   // 执行模式（2 个）
```

**状态机视角**：`PENDING → READY → COMPLETED`（`promoteNextStep` 干的）；`PAUSED/WAITING_FOR_CONFIRMATION` = **中间态**（等事件推动）；`COMPLETED/FAILED/CANCELLED` = **终态**（不会再变）。

---

## 1. 枚举是什么？——"有限选项的固定清单"

**前端对照**：TS 的 `type ExecutionMode = "SYNC" | "ASYNC"`（union）/ `enum`——同一味。

---

## 2. 三大价值（"为什么不用 String / int"）

| # | 价值 | 对比 String |
|---|------|------------|
| 1 | **类型安全** | `"RUNING"`（拼错）→ 编译器不管、静默污染数据；`TaskStatus.RUNING` → **当场标红** |
| 2 | **自文档** | `String status` 猜吧；`TaskStatus status` → IDE 一打点，**9 个合法值全列出** |
| 3 | **switch 穷尽检查** | 漏写分支 → **编译不过**（String 版本永远不查） |

**int 更惨**：`setStatus(3)`——"3 是什么？"——靠注释——**注释会撒谎**。

> **金句**：**枚举收走"可能写错的自由"，换来编译器替你站岗**——错误发现时机从"半夜生产"提前到"写代码那一秒"。

---

## 3. 带字段的枚举——`LOW(1, "低")` 语法

```java
enum Priority {
    LOW(1, "低"), MEDIUM(2, "中"), HIGH(3, "高");   // 值后面的括号 = "给值传参数"
    private final int level;
    private final String label;
    Priority(int level, String label) { ... }        // 它们"出生"时调用的配方
    boolean isUrgent() { return level >= 3; }         // 枚举也能有方法
}
```

**概念上**：`LOW = new Priority(1, "低")`——JVM 在**类加载时**替你造三个实例。

**四个要点**：
1. **每个枚举值 = 该枚举类的实例，且全局唯一（单例）**；
2. **枚举构造器只能是 `private`**（自动——外面 `new` 不了）——**这就是"有限清单"的物理保障**；
3. **字段建议 final**（造完锁死）；
4. **私有字段在"类内部"可访问**（`p.level` 在 `Priority` 内部合法——J1 的访问控制）。

**设计动机**：**"数据贴着值走"**——否则需要一堆 `if (p == LOW) return 1; ...` 或另配映射表。

---

## 4. 三大内置工具（每个枚举白送）

| 工具 | 用途 | 实测 |
|------|------|------|
| `values()` | 全部值（数组） | 遍历打印 ✓ |
| `valueOf("HIGH")` | 字符串 → 枚举 | `解析: HIGH` ✓（字符串对不上会抛异常） |
| `ordinal()` | 序号（从 0） | `HIGH` 的 `ordinal()=2` ✓ |

## 5. ★ 穷尽实验（"编译器站岗"现场，2026-10-07 实测）

```java
static String describe(Priority p) {
    return switch (p) {           // 箭头 switch（Java 14+）
        case LOW -> "不急";
        case MEDIUM -> "还行";
        // case HIGH -> "马上办";   ← 注释掉它
    };
}
```

**实测结果**：

```text
Exception in thread "main" java.lang.Error: Unresolved compilation problem:
        A Switch expression should cover all possible values
        at EnumLab.describe(exampleJavaGrammar.java:59)
```

**三重看点**：
1. **报错原文** = "**A Switch expression should cover all possible values**"——"你没覆盖全！"；
2. **以"运行时异常"形式出现**——因为这是 IDE（JDT）的"**宽容运行**"：编译失败时生成"一跑就炸的壳"——**编译错误穿上运行时的马甲**——报错信息里还**精确给出了位置**；
3. **`java.lang.Error`**——**J4 家族树的"另一支"**（Error ≠ Exception——IDE 的这招制造的就是 Error）。

**对照**：传统 `switch` **语句**漏分支只是"不报"（掉进没有分支的坑）；**箭头 switch 表达式是硬性穷尽**（漏一个，编译不过）——这就是枚举的第三大价值的"实物"。

## 6. 枚举在项目里的三处身影

| 场景 | 机制 |
|------|------|
| **进数据库** | `@Enumerated(EnumType.STRING)`（`TaskEventLogEntity` 见过）——**存"名字字符串"**（读库的人也能看懂） |
| **进 JSON** | API 响应里 `"status":"WAITING_FOR_CONFIRMATION"`——**枚举序列化成字符串**（前端直接可读） |
| **驱动流程** | `switch (step.getStatus())` / `allMatch(s -> s.getStatus() == COMPLETED)`（J5）——**状态机的大脑** |

## 补充：思考题与答案（课堂问答收录）

**题 1**——`TaskStatus` 为什么不写成 `String`（"DRAFT"/"RUNNING"）或 `int`（0/1/2）？

**答**：**让编译器替你干活**——分两层看"两种错误"：

| 错误类型 | 用 String | 用枚举 |
|---------|----------|--------|
| **拼写错**（`"RUNING"` vs `TaskStatus.RUNING`） | 编译器**不管**——要么某天运行时炸，要么**静默污染数据**；50 处魔法字符串改一处漏一处 | **当场标红**（`RUNING` 不存在） |
| **想不起合法值** | 翻文档/猜 | **IDE 打点全列出** |

**int 更惨**：`setStatus(3)`——"3 是什么？"——要靠注释——**而注释会撒谎**。

> **金句**：**枚举收走"可能写错的自由"——换来编译器替你站岗**——把"错误发现时机"从"半夜生产"提前到"写代码那一秒"。

**题 2（业务语义题）**——`CANCELLED` 和 `FAILED` 的区别？`PAUSED` 呢？

**答**：两个维度——**谁按的"结束键" + 能不能回来**：

| 状态 | 谁按的键 | 能回来吗 | 一句话 |
|------|---------|---------|--------|
| **FAILED** | **系统**（自己跑挂了） | ❌ | "**意外死亡**"——你不想停，它出事了 |
| **CANCELLED** | **人**（主动取消） | ❌ 终态 | "**主动终止**"——"我不玩了" |
| **PAUSED** | **人**（暂停） | ✅ **可 resume** | "**中场休息**"——不是死，是等 |

**为什么区分值钱**：**FAILED 要报警**（系统问题）、**CANCELLED 不用**（用户意图）——同一句"任务结束了"，**后续动作完全不同**；恢复逻辑也不同（PAUSED 能续跑、CANCELLED 得重开）。

**顺带立概念**：**终态 vs 中间态**——`COMPLETED / FAILED / CANCELLED` 是**终态**（不会再变）；`PAUSED / WAITING_FOR_CONFIRMATION` 是**中间态**（等事件推动）。

## 附：本课一句话总结

1. **枚举 = 有限选项的固定清单**——拼错编译不过、IDE 全列、switch 穷尽；
2. **值是"带参出生的单例实例"**（`LOW(1,"低")` ↔ `new Priority(1,"低")`）；
3. **构造器自动 private**——"全世界只有这几个值"的物理保障；
4. **三工具**：`values()` / `valueOf()` / `ordinal()`；
5. **"编译器站岗"**：漏 case 的箭头 switch——**编译就过不去**（IDE 里以 Error 的形式炸给你看）。

## 7. 进阶一：枚举的隐藏机制（2026-10-27 补，面试级）

### 7.1 `values()` / `valueOf` 的三个真相

```java
// ① values() 每次调用都返回【新数组】（不是缓存）——循环里反复调有开销
for (TaskStatus s : TaskStatus.values()) { ... }   // 每圈新数组？不，foreach 只调一次
                                                   // 但写 while 里反复 .values() 就浪费了

// ② valueOf("不存在") 抛 IllegalArgumentException（不是返回 null！）
TaskStatus.valueOf("不存在");   // 💥 输入不可信时必须 try-catch 或先遍历比对

// ③ ordinal() 是【声明顺序】（0 起）——不要拿它持久化/传输
//    改一行声明顺序 = 全部数据错乱。要持久化就存 name() 字符串
```

### 7.2 枚举常量是天然单例（《Effective Java》item 3）

```text
JVM 类加载时创建每个常量的唯一实例 → 天然线程安全
枚举单例是书里推荐的最佳单例写法——因为它还防两种攻击：
  · 反射攻击：JVM 层面禁止 new 枚举（newInstance 直接抛异常）
  · 序列化攻击：反序列化只走 valueOf(name)，不会产生第二个实例
```

```java
// 枚举单例（一行搞定，防反射+防序列化）
public enum ConfigHolder {
    INSTANCE;
    private final Map<String, String> config = load();
}
```

### 7.3 枚举不能继承，但能实现接口

```java
public enum TaskStatus implements Describable {   // ✅ 实现接口可以
    PENDING("待开始"), RUNNING("进行中");

    @Override public String describe() { return label; }   // 每个常量可各自实现
}

public enum X extends BaseEnum { ... }             // ❌ 编译错：enum 隐式 final
// 想要"枚举继承"的效果：接口 + 两个枚举各自实现
```

## 8. 进阶二：EnumMap / EnumSet（面试加分项）

| 工具 | 内部实现 | 性能 | 场景 |
|---|---|---|---|
| **EnumMap** | 数组（下标 = ordinal） | O(1)，比 HashMap 快且省 | 按枚举键存取/分组 |
| **EnumSet** | 位向量（long 的 bit） | 极省内存，集合运算快 | 枚举子集（权限/开关组合） |

```java
// 按任务状态分组计数——用 EnumMap 而不是 HashMap
Map<TaskStatus, Long> count = tasks.stream()
        .collect(groupingBy(Task::getStatus,
                            () -> new EnumMap<>(TaskStatus.class),
                            counting()));
```

**为什么快**：`map.get(TaskStatus.RUNNING)` 内部就是 `array[RUNNING.ordinal()]`——数组下标直达，不用 hash。

## 9. 进阶三：项目 15 个枚举的分类学（2026-10-27 实测盘点）

| 类别 | 项目枚举 | 特征 |
|---|---|---|
| **状态机类** | TaskStatus / StepStatus / PlanStatus / ExecutionStatus / ReportStatus / FetchStatus / ConfirmationStatus | 有流转方向（待→跑→成/败），是业务的骨架 |
| 模式/开关类 | ExecutionMode | SYNC / ASYNC——影响执行路径的选择 |
| 类型/标签类 | StepType / SourceType / EventType / ConfirmationType / OperatorType | 平铺分类，无流转 |
| 结果类 | AuditResult | SUCCESS / FAILURE——二元判定 |

### TaskStatus 状态机（本项目的业务骨架）

```text
PENDING ──start──→ RUNNING ──┬──→ COMPLETED
   │                          └──→ FAILED
   └──cancel──→ CANCELLED
   （requiresConfirmation 分支：PENDING → WAIT_CONFIRMATION → RUNNING）
```

**枚举 = 状态机的合法状态集合**——非法状态（如 PENDING 直接跳 COMPLETED）在代码里无枚举可表达，天然防呆。

## 10. 面试级问答（2026-10-27）

**Q1：枚举 vs 常量类（`static final int`）？**

```text
① 类型安全：传 99 给期望 TaskStatus 的地方，编译器直接报错（本课 §5 穷尽实验）
② 自带命名空间与遍历能力（values）
③ 可带字段/方法/构造器（行为与数据绑定）
④ 天然单例、线程安全
⑤ 专属容器（EnumMap/EnumSet）性能碾压
```

**Q2：枚举线程安全吗？**

```text
常量本身：安全（类加载时创建、引用不可变）
枚举的【字段】可变时要自己保证——最佳实践：字段全 final（项目 15 个枚举全部如此）
```

**Q3：枚举能被反射 new 出来吗？**

```text
不能——JVM 层面禁止（Constructor.newInstance 对枚举抛 IllegalArgumentException）
这正是"枚举是最佳单例"的底气（普通单例可被反射破坏）
```

**Q4：枚举怎么序列化/反序列化？**

```text
序列化只存 name()；反序列化走 valueOf(name)——返回同一实例，不会产生副本
（ Jackson 对枚举默认也是 by-name；不匹配时抛异常而非静默 null——要留意 API 输入）
```

### 一句话

```text
枚举 = 有限选项 + 类型安全 + 单例 + 可带行为
进阶三件套：valueOf 的坑（抛异常）、EnumMap 的快（数组直达）、枚举单例的稳（防反射防序列化）
```
