# J2 · 接口与多态（精读讲义）

> **教材**：`TaskEventLogStore`（接口）+ `JpaTaskEventLogStore` / `MyBatisTaskEventLogStore`（两实现）+ `PersistenceModeDemoRunner`（启动演示）+ `TaskEventService`（调用方）
> **一句话主题**：**一个接口，两副面孔**——"合同"如何让两套持久化实现随时切换、业务代码零改动。
> **建立**：2026-10-04（含本地双模式实测记录）

---

## 0. 教材原文（先通读一遍）

**合同**（`TaskEventLogStore.java`，14 行）：

```java
public interface TaskEventLogStore {
    void save(TaskEventLogEntity eventLogEntity);
    List<TaskEventLogEntity> findByTaskIdOrderByCreatedAtDesc(UUID taskId);
}
```

> Javadoc 点题：*"Service 层只依赖本接口，不感知底层实现，切换无需改动业务代码。"*

**面孔 A（默认）**：`JpaTaskEventLogStore` —— `@ConditionalOnProperty(name="app.persistence.mode", havingValue="jpa", matchIfMissing=true)`，save 一行 `repository.save(...)`。

**面孔 B（可切换）**：`MyBatisTaskEventLogStore` —— `@ConditionalOnProperty(name="app.persistence.mode", havingValue="mybatis")`，save 手动补主键 + `mapper.insert(...)`。

**报幕员**：`PersistenceModeDemoRunner` —— `@Component @Profile("dev")` + `implements CommandLineRunner`。

**使用者**：`TaskEventService` —— 构造器注入接口类型，永远只见合同。

## 1. 起点问题：如果不用接口，写死会怎样？

```java
private final JpaTaskEventLogStore store;   // ❌ 直接依赖"具体的人"
```

| # | 麻烦 |
|---|------|
| 1 | **换实现要动业务代码**：切 MyBatis → Service 的字段/构造器/import 全要改 |
| 2 | **测试难**：想塞"假实现"不连数据库——塞不进去 |
| 3 | **两套共存没法做**：Service 只能跟其中一个签死 |

**解药**：中间加一份**合同**——Service 只跟合同签，**谁持合同谁上岗**。

> **前端类比**：组件不直接 `import axios`，而是封一个 `api` 模块——将来换 fetch/GraphQL，组件零改动。

---

## 2. `interface`：合同长什么样

- **不是 class，不能 `new`**——它是"形状的声明"；
- 方法**只有签名、没有花括号**——"只写做什么，不写怎么做"；
- **TS 近亲**：

```typescript
interface TaskEventLogStore {
  save(entity: TaskEventLogEntity): void;
  findByTaskIdOrderByCreatedAtDesc(taskId: string): TaskEventLogEntity[];
}
```

> 区别：TS 的 interface 是**纯编译期**的（编译完消失）；Java 的 interface **运行时真实存在**——"谁实现了它"进程是知道的——**这是多态的物理基础**。

---

## 3. `implements` 与 `@Override`：签名画押与履行标记

| 关键词 | 角色 |
|--------|------|
| `implements TaskEventLogStore` | **签名画押**——"我是这样的家伙"——签了必须全做到（方法一个不少、签名一模一样，否则**编译不过**） |
| `@Override` | **履行标记**——给编译器校验："这方法确实在合同里"（名字/参数写错当场报） |

---

## 4. 两副面孔：同一个 `save()`，两种活法

| 维度 | JPA 版 | MyBatis 版 |
|------|--------|-----------|
| 手里拿着谁 | `TaskEventLogRepository` | `TaskEventLogMapper` |
| SQL 哪来 | **框架自动生成** | **XML 手写** |
| 主键哪来 | `@GeneratedValue`（框架生成） | **代码手动 `setId(UUID.randomUUID())`** |
| save 内部做几件事 | 1 件 | 2 件（补主键 + insert） |
| 出场条件 | `mode=jpa` **或没配置** | `mode=mybatis` |

**调用方看到的**（两套实现通用，写一遍）：

```java
taskEventLogStore.save(event);   // ← Service 里就这一行
```

**接口的意义**：**把差异挡住，把一致露出来。**

## 5. ★ 声明类型 vs 运行时类型（本课的心脏）

```java
TaskEventLogStore store = new JpaTaskEventLogStore(repo);
//    ↑ 声明类型（编译期）            ↑ 运行时类型（真身）
```

| | 声明类型（左边） | 运行时类型（右边） |
|---|---|---|
| 谁定 | 变量声明时 | `new` 那一刻定死 |
| 谁看 | **编译器** | **JVM** |
| 决定 | 变量**能调哪些方法**（只认合同） | 实际**执行哪段代码**（真身说了算） |

**口诀：编译看左边，运行看右边。**

**"门牌号/房子"模型**：

```text
store 变量   = 门牌号（写着"TaskEventLogStore 这栋楼"）
对象本尊     = 房子（真身：JPA 房 / MyBatis 房）
getClass()  = 敲门问房子"你是谁"——房子不撒谎
```

## 6. `getClass()`：对象的"出生证"

- 每个对象出生时带一张"出生证"（`new` 那刻写死）；
- `getClass()` = 掏出看；`getSimpleName()` = 只看名字；
- 人人都有——它是 `Object` 类的方法（万物之母）。

**前端同款**：`store.constructor.name` / `instanceof`。

---

## 7. `@ConditionalOnProperty`：谁上场的"裁判规则"

```java
@ConditionalOnProperty(name = "app.persistence.mode", havingValue = "jpa", matchIfMissing = true)
```

| 参数 | 含义 |
|------|------|
| `name` | 去哪个配置项取值 |
| `havingValue` | 期望值（等于它才放行） |
| `matchIfMissing` | **配置项整个缺失时也放行**（= 默认我上） |

**★ 配置真身**（`application.yml`，值不在 Java 里！）：

```yaml
app:
  persistence:
    mode: ${APP_PERSISTENCE_MODE:jpa}
```

- `${ENV:默认值}` = **环境变量优先，没有则用默认**（与 K8s 清单 env 注入闭环）；
- **双保险**：占位符默认 `jpa` + `matchIfMissing=true`。

### 注解心智：贴给"读者"看的标签

| 注解 | 读者 | 何时读 |
|------|------|--------|
| `@Override` | **编译器** | 编译时 |
| `@Repository` / `@ConditionalOnProperty` | **Spring** | ★ **启动时** |

> **前端类比**：TS 装饰器（NestJS `@Controller`）——框架启动时扫描读取。

---

## 8. Spring 三步裁判（扫描 → 条件 → 注入）

```text
① 扫描报名：@Repository 让类进入候选池（JPA、MyBatis 都举手）
② 条件裁判：读注解 → 去配置源取 mode 的值 → 与 havingValue 比对 → 决定"注册不注册"
   （落选者根本不进容器——淘汰发生在注册阶段）
③ 注入：唯一幸存者被塞进 TaskEventService 的构造器
```

**易撞的报错预告**：
- **两个都活** → `NoUniqueBeanDefinitionException`（不知道选谁）；
- **一个都没活** → `NoSuchBeanDefinitionException`（没人干活）。

**重要澄清**：切换**不是运行时动态生成实现**——两个实现类编译时就躺在 jar 里——"切换"只是"选谁注册成 bean"。

## 9. IoC 与钩子：DemoRunner 无人调用却自动执行之谜

**三层机制接力**：

1. `@Component` → Spring 扫描时**替你 `new`**（对象进容器）；
2. `implements CommandLineRunner` → **约定钩子**："启动后叫我"；
3. `SpringApplication.run()` 流程最后一站 **`callRunners()`** → 逐个调 `run()`。

```text
启动流程：扫描 → 建 bean → 起 Tomcat → "Started ... in X seconds" → ★ callRunners()
```

**行话**：**控制反转（IoC）** + **好莱坞原则**（"Don't call us, we'll call you."）。

| 前端场景 | 谁在何时调你 |
|---------|-------------|
| `useEffect(() => {}, [])` | React 挂载后 |
| `onMounted(() => {})` | Vue 挂载后 |
| `addEventListener('DOMContentLoaded', fn)` | 浏览器 |
| `implements CommandLineRunner` | **Spring 启动完成后** |

**铁证**：日志顺序 `Started ... in X seconds` → `========== 持久化模式演示开始 ==========`。

## 10. 钩子家族与"不背清单"的查证法

**时间轴心智**（替代背诵）：

```text
启动中 ── @PostConstruct（每个 bean 出生后）
启动完成 ─ ★ CommandLineRunner / ApplicationRunner
运行中 ── @Scheduled / @EventListener
关闭时 ── @PreDestroy / DisposableBean
```

**查证四条路**：

| # | 路 | 怎么做 |
|---|-----|--------|
| A | **IDE 补全 + Javadoc** ★ 日常首选 | `implements ` 打字母弹候选；Ctrl+点进接口读 Javadoc（一手权威就在源码旁） |
| B | 官方文档 | 搜节名：`Using the ApplicationRunner or CommandLineRunner` |
| C | 源码顺藤摸瓜 | `SpringApplication.run()` → `callRunners()` |
| D | 搜索/AI | 兜底 |

> **方法论**：**查证 > 记忆**——背清单必输（框架每版都在加）。

## 11. 反射入门：`Class` 是类的"说明书"

```java
// 本类声明的方法（普通类适用；代理类见第 12 节）
for (Method m : obj.getClass().getDeclaredMethods()) { ... }

// 全部公开方法（含继承——长）
for (Method m : obj.getClass().getMethods()) { ... }

// 实现了哪些接口（"合同清单"）
for (Class<?> i : obj.getClass().getInterfaces()) { ... }
```

**前端类比**：`console.dir(obj)` / `Object.getOwnPropertyNames(Cls.prototype)`。

**更实用**：日常查方法**直接看接口源码 / IDE 点开类**——不用写代码。

> **大串联**：Spring 的一切魔法（扫描注解、注入依赖、生成代理）底层全是**反射**。

## 12. CGLIB 代理：`getClass()` 可能是"戏服身份"

实测报幕：`JpaTaskEventLogStore$$SpringCGLIB$$0` / `MyBatisTaskEventLogStore$$SpringCGLIB$$0`

```text
MyBatisTaskEventLogStore                    ← 真身
        ↑ 继承（运行时动态生成）
MyBatisTaskEventLogStore$$SpringCGLIB$$0    ← 代理子类（"戏服"）
```

- **为什么套戏服**：AOP——在方法调用前后加逻辑（`@Repository` 常见用途 = **异常翻译**）；
- **看真身**：`obj.getClass().getSuperclass()`；
- **戏服不改合同**：`getInterfaces()` 里依然是 `TaskEventLogStore`——所以调用方无感知。

**反射里的实物证据**（代理类的方法清单）：

```text
public final void ...$$SpringCGLIB$$0.save(...)     ← 代理重写的 save（拦一手）
final void ...CGLIB$save$0(...)                      ← ★ 原方法备份（放行时调它）
CGLIB$BIND_CALLBACKS / CGLIB$STATICHOOK9             ← CGLIB 机械零件
```

> 校准：对**代理类**用 `getDeclaredMethods()` 列表**很长**（全是 CGLIB 机械）——想看干净清单应 `getSuperclass().getDeclaredMethods()`。

## 13. 日志方法学：SLF4J 占位符配对规则

```java
LOGGER.info("演示数据：taskId={}，当前实现={}", UUID.randomUUID(), store.getClass().getSimpleName());
```

| 情况 | 结果 |
|------|------|
| 参数 **多于** `{}` | ★ **多余的静默丢弃**（不报错——排查陷阱） |
| 参数 **少于** `{}` | 剩余 `{}` 原样出现在输出 |
| **最后一个是异常对象** | ★ **例外**：无占位符也打印完整堆栈（`error("msg", e)` 惯用法） |

**Logger 行的零件**（`private static final Logger LOGGER = LoggerFactory.getLogger(X.class)`）：
- `Logger` 是**接口**；`LoggerFactory.getLogger` 是**工厂方法**；
- 传 `.class` = **给 logger 上户口（名字=类名）**——用途：**按名字分级过滤**：

```yaml
logging:
  level:
    org.hibernate.SQL: debug                     # ← 命中 Hibernate 的 SQL 日志
    com.aiexplorer...store.mybatis: debug        # ← 命中 MyBatis Mapper 的 SQL 日志
```

**`System.out.println` vs `LOGGER`**：级别 / 运行时开关 / 按类过滤 / 自动格式 / 惰性求值 / 落盘采集——全无 vs 全有（println ≈ `console.log`，生产 bad practice）。

## 14. 动手实操记录（2026-10-04 实测）

**玩法**：本地 dev 启动（H2 文件库 + Nacos optional），用一个环境变量切模式：

```powershell
$env:SPRING_PROFILES_ACTIVE = "dev"
$env:SPRING_CLOUD_NACOS_DISCOVERY_ENABLED = "false"   # 防止开发机注册进集群（另见彩蛋）
mvn spring-boot:run                                    # JPA 幕（默认）

$env:APP_PERSISTENCE_MODE = "mybatis"
mvn spring-boot:run                                    # MyBatis 幕
```

**两幕对照表**（核心成果）：

| 对比点 | JPA 幕 | MyBatis 幕 |
|--------|--------|-----------|
| 报幕类名 | `JpaTaskEventLogStore$$SpringCGLIB$$0` | `MyBatisTaskEventLogStore$$SpringCGLIB$$0` |
| SQL 形态 | **多行格式化**（自动排版） | **单行**（手写原文） |
| 来源指纹 | 无手工痕迹 | ★ **`CAST(? AS JSON)`** + TypeHandler 手写痕迹 |
| 字段顺序 | **字母序**（`created_at` 打头——自动生成特征） | **手写顺序**（`id` 打头——XML 原文顺序） |
| 参数日志 | `binding parameter (1:TIMESTAMP_WITH_TIMEZONE) <- [值]`（逐行 + Hibernate 类型系统） | `<== Parameters: a7a34b...(UUID), ...`（一行 + 类型标注） |
| SELECT | **自动表别名** `tele1_0.task_id`（Hibernate 生成特征） | 手写列名（无别名） |
| 行数反馈 | （无显式计数行） | `<== Updates: 1` / `<== Total: 1` |
| id 来源 | **Hibernate 框架生成** | ★ **代码手动 `setId(UUID.randomUUID())`** |

**彩蛋记录**：
- **优雅停机**：Ctrl+C 时日志出现 `De-registering from Nacos Server now...` + `[DEREGISTER-SERVICE]`（**先摘牌再退出**——`server.shutdown: graceful` 生效）；
- **开发机进注册中心**：不禁注册时，本地实例（`192.168.80.37:8080`）真实注册进集群 Nacos——"注册 → 心跳 → 摘牌"完整生命周期走了一遍（**生产注意**：本地实例会污染共享环境，除非专门实验否则应禁用注册）；
- 停机时的 `NotifyCenter Event listener exception: java.lang.InterruptedException` —— **无害噪音**（关闭钩子打断监听线程的正常现象）。
