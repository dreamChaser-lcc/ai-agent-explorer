# 04 · 缓存三件套——穿透 / 击穿 / 雪崩

> **状态**：⬜ 未学习 ｜ **下一课**：05·分布式锁深入

---

## 三种病一张图

| 病 | 现象 | 根因 | 解药 |
|---|---|---|---|
| **穿透** | 查"根本不存在"的 key | 恶意/脏数据，缓存永远 miss | 缓存空值 / **布隆过滤器** |
| **击穿** | 热点 key 过期瞬间 | 千万并发同时打到 DB | 互斥重建 / 逻辑过期 |
| **雪崩** | 大量 key 同时过期（或 Redis 挂） | 同一时刻集体失效 | TTL 加随机 / 集群高可用 |

```text
穿透 vs 击穿 vs 雪崩（一句话分清）：
穿透 = 东西【不存在】（无中生有的请求）
击穿 = 【一个】热点过期（众矢之的）
雪崩 = 【一片】key 失效（集体塌方）
```

## 解药细节

```text
① 穿透：
   缓存空值：DB 查无 → 存 null 短 TTL（防脏）——对"随机 key 攻击"没用
   布隆过滤器：提前拦截"肯定不存在"（有极小误判率，不漏判）
   ② 击穿：
   互斥重建：只放一个线程去查 DB 回填，其余等待（= 单飞 singleflight）
   逻辑过期：不设真 TTL，值里带过期时间，异步刷新
   ③ 雪崩：
   TTL = 基础值 + random(0, 300s) 打散
   高可用：哨兵/集群（07 课）+ 服务层熔断限流兜底
```

## 项目关联（项目当前是"直连 DB"，以下按"加了缓存层"畅想）

```text
TaskDetail 查询加缓存的正确姿势（伪代码）：
  key = "task:" + id
  if (cache.has(key)) return cache.get(key);     // ① 命中
  task = db.find(id);
  if (task == null) {
      cache.set(key, EMPTY, 60s);                // ② 空值缓存（穿透解药）
      return null;
  }
  cache.set(key, task, 300 + random(60));        // ③ TTL 随机化（雪崩解药）
场景⑨ 的执行锁已实践"Redis 互斥"——击穿的"互斥重建"同一思想
```

## 面试速答

```text
Q：三件套分别防什么？ A：不存在防穿透（空值/布隆）、
   热点过期防击穿（互斥/逻辑过期）、集体失效防雪崩（随机 TTL+高可用）。
Q：布隆过滤器为什么能防穿透？
A：说"不存在"就一定不存在（不漏判，只误判）——把攻击拦在缓存之前。
```

## 一句话

```text
不存在→穿透（空值+布隆）；单热点→击穿（互斥）；一片倒→雪崩（随机TTL+HA）。
所有解药共同思想：把流量挡在 DB 之外。
```
