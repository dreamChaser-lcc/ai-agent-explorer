## 一张表认全（类型 → 底层 → 场景）

| 类型 | 底层数据结构 | 典型场景 | 项目联想 |
|---|---|---|---|
| **String** | SDS（简单动态字符串） | 缓存对象/计数器/分布式锁 key | 场景⑨ 的锁 key |
| **Hash** | 压缩列表(小)/哈希表 | 对象的部分字段读写 | 缓存 Task 详情 |
| **List** | 压缩列表(小)/双端链表 | 消息队列/时间线 | 简易队列 |
| **Set** | 哈希表 | 去重/共同好友 | 幂等键去重（备选） |
| **ZSet** | **跳表**(数据结构 09) + 哈希 | 排行榜/范围 | 任务时间线排序 |

## String 的底层不是 String

```text
SDS（Simple Dynamic String）比 Java String 强的三点：
  ① 头部记长度 → O(1) 取 len（C 风格 strlen 是 O(n)）
  ② 空间预分配 → 拼接少 realloc
  ③ 按长度判结尾 → 二进制安全（能存图片字节）
```

## ZSet 的跳表（复习[数据结构 09](../数据结构实战/09·图与收网：知识地图.md) [网页版](https://github.com/dreamChaser-lcc/ai-agent-explorer/blob/main/docs/数据结构实战/09·图与收网：知识地图.md)）

```text
为什么 Redis 用跳表不用红黑树？
  ① 实现简单 100 行 vs 红黑树几百行
  ② 范围查询（ZRANGEBYSCORE）链表直扫，同样高效
  ③ 并发修改更友好
O(log n) 查找/插入——多级"高速公路索引"的思想
```

## 面试速答

```text
Q：ZSet 底层？ A：跳表+哈希（哈希管 O(1) 查分，跳表管排序范围）。
Q：Hash 什么时候哈希表什么时候压缩列表？ A：元素少且短用压缩列表省内存。
```

## 一句话

```text
五大类型 = 五套底层结构的"门面"。
SDS（String）与跳表（ZSet）是两个最高频考点。
```
